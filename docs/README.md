## 문서를 갱신하는 기준

- 현재 동작을 규정하는 계약은 구현 정책에, 이를 선택한 이유는 개발자 가이드에 둡니다. 상세 계약은 한 곳에서 관리하고 다른 문서는 링크로 연결합니다.
- 개발 히스토리에는 사용자에게 영향을 주는 변경과 안정 버전 지정만 적습니다. 검증 수치·배포 해시는 내부 보고서에 둡니다.
- 성능은 `tools/benchmark.py`로 측정해 기준선과 비교합니다. 기준선은 안정 버전을 선언할 때만 바꿉니다.
- 보관 폴더의 문서는 고치지 않습니다(깨진 링크만 고칩니다). 예전 경위가 필요하면 현재 문서에서 링크로 연결합니다.

각 문서는 1부터 시작하는 독립적인 절 번호를 사용합니다.
