## 문서를 갱신하는 기준

- 현재 동작을 규정하는 계약은 구현 정책에, 이를 선택한 이유는 개발자 가이드에 둡니다. 상세 계약은 한 곳에서 관리하고 다른 문서는 링크로 연결합니다.
- 반려·보류 기록은 상태와 이유를 함께 남깁니다. 확인되지 않은 이유나 개선 효과는 추정하지 않습니다. 상세 실험 수치는 성능 개선 기록에 연결합니다.
- 개발 히스토리는 적용 버전과 확인 가능한 커밋을 기준으로 작성합니다. 버전이 바뀌지 않은 테스트·도구·문서 보완도 해당 버전의 후속 항목으로 기록합니다. 작업본 실험을 배포 버전에 소급하지 않습니다.
- 새 기능은 해당 사용자 설명·구현 계약·개발 절차·버전 이력을 함께 확인합니다. 과거 측정 원본과 당시 배포 기록은 유지합니다.

각 문서는 1부터 시작하는 독립적인 절 번호를 사용합니다. 다른 문서의 계약을 참조할 때는 문서명과 해당 절의 링크를 함께 표시합니다.
