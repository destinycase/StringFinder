# StringFinder 5.9.2 재검증 및 수정 계획

- 기준 소스: `d0d0f5f` — Rust 코드 포맷 표준화
- 기준 엔진: 배포된 `sf_engine.ENGINE_VERSION == 5.9.2`
- 작성일: 2026-09-07
- 상태: R01~R08 구현 및 검증 완료 (후속 기록은 6절)
- 목적: 검색 결과 무결성과 검색 속도를 유지하면서 유효한 리뷰 항목을 수정한다.

## 1. 재검증 결론

이전 리뷰의 8개 항목은 모두 근거가 유지된다. 다만 사용자 경로에서의 발생 조건, 실측 결과의 해석, 정리 항목의 심각도를 아래처럼 구분한다.

| ID | 항목 | 판정 | 심각도 | 증거 |
|---|---|---|---|---|
| R01 | 이전 비동기 정렬이 새 검색 결과를 덮어씀 | 유효 | 높음 | 완료 순서를 통제한 모델 재현 + UI 호출 경로 확인 |
| R02 | XML 상한 이후 일부 속성 구문 검증 누락 | 유효 | 높음 | 동일 문서가 상한 값에 따라 성공/구문 오류로 달라짐 |
| R03 | XML 빈 요소의 속성 경로 오류 | 유효 | 중간 | 같은 태그명·접미사 태그명 입력에서 잘못된 경로 재현 |
| R04 | XML 속성의 행 번호·바이트 위치 오류 | 유효 | 중간 | 값은 2행/offset 25인데 1행/offset 6 반환 |
| R05 | Non-UTF8 긴 줄의 반복 탐색 및 취소 지연 | 유효 | 중간 | UTF-16 입력 크기별 측정 및 취소 비교 |
| R06 | 깊은 XML의 전체 경로 반복 생성 | 유효 | 중간 | 무매치 문서에서 깊이 증가에 따른 비선형 시간 증가 |
| R07 | 빌드 도구의 외부 프로세스 강제 종료 | 유효 | 중간 | 종료 대상 제한 없는 코드 및 빌드 호출 경로 확인 |
| R08 | 미사용 데이터 전달·중복 타입·잘못된 주석 | 유효 | 낮음 | 참조 및 사용처 확인 |

심각도는 현재 확인된 영향 기준이다. R07은 빌드 환경의 미저장 데이터 손실 위험이며 배포 앱의 원격 코드 실행 취약점으로 분류하지 않는다. R08의 경고 억제 자체가 실제 데드 코드의 존재를 증명하는 것은 아니다.

### 검증 범위와 한계

- R01은 Qt 모델의 정렬 워커 실행을 보류했다가 완료시키는 방식으로 유효한 작업 순서를 재현했다. 실제 사용자 클릭으로 발생 빈도를 측정한 것은 아니다.
- R02~R06은 임시 입력을 만들어 배포된 5.9.2 엔진으로 다시 실행했다. 포맷 커밋 전후의 실행 로직은 동일하다.
- R07은 실제 프로세스를 종료하지 않고 코드로 확인했다. 수정 검증도 소유 관계와 종료 함수를 모킹해 수행한다.
- 측정 시간은 이 장비에서의 참고값이다. 성능 합격 여부는 동일 실행 조건의 수정 전후 반복 비교로 결정한다.
- 직전 코드 리뷰에서 Rust 37개, Python 368개 통과(1개 스킵, 10개 제외), Ruff·mypy·Clippy·포맷 검사가 통과했다. 이번 재검증에서는 해당 결과를 재사용하고, 아래 경계 조건을 다시 확인했다. 기존 테스트 통과가 이 이슈들을 부정하지 않는다.
- 계획서 작성 단계에서는 이 문서만 생성했다. 이후 승인된 구현·검증 결과는 6절에 기록한다. 버전 변경·배포·커밋은 별도 요청 대상이다.

## 2. 항목별 수정 설계

### R01. 이전 정렬 결과 무효화

관련 코드:

- [SearchResultModel](../src/ui/models.py): `sort`, `sort_globally`, `_on_sort_finished`, `clear`, `add_results`
- [SearchTab](../src/ui/search_tab.py): 검색 시작의 결과 초기화 및 검색 완료의 정렬 요청
- [ResultView](../src/ui/result_view.py): `set_searching_state`

**재검증 근거**

현재 정렬은 결과 버퍼의 복사본으로 실행되고, 완료 콜백은 현재 버퍼를 무조건 교체한다. `clear()`는 진행 중인 정렬을 무효화하지 않는다.

1. `old.txt` 결과로 정렬 요청.
2. 정렬 완료 전에 `clear()` 실행.
3. 새 검색 결과 `new.txt` 추가.
4. 이전 정렬 완료.
5. 최종 버퍼가 `['old.txt']`가 됨을 다시 확인.

검색 중에는 헤더 정렬이 비활성화되므로 일반적인 검색 중 클릭 문제로 과장하지 않는다. 검색 완료 때 시작된 정렬이 끝나기 전에 다음 검색을 시작하는 경합은 여전히 가능하다. 정렬 중 결과를 추가하는 모델 수준 경로에서도 복사본에 없는 신규 결과가 유실된다.

**수정 방향**

- 결과 데이터 변경을 나타내는 세대 번호와 정렬 요청 식별자를 둔다.
- `clear()` 및 결과 추가 시 데이터 변경을 기록한다.
- 정렬 결과에는 시작 시점 식별자를 포함한다. 현재 데이터/요청과 맞지 않으면 적용하지 않는다.
- 오래된 완료 콜백이 새로운 정렬의 `_is_sorting`, 워커 참조, 완료 신호를 건드리지 않도록 한다.
- 데이터가 바뀐 정렬은 보류 또는 필요 시 한 번 재요청한다. 결과 배치마다 전체 정렬을 재실행하지 않는다.
- 정렬 실패를 빈 결과 목록으로 대체하지 않고 기존 데이터를 보존하도록 완료 상태를 구분한다.
- Qt 모델 변경 알림을 실제 데이터 교체 시점에 맞춘다. 백그라운드 작업 전체 동안 모델 변경 알림 구간을 열어두지 않는다.
- 워커의 실행·종료 수명은 유지한다. 취소 표시만으로 실행 중인 QRunnable/QObject를 즉시 파괴하지 않는다.

**합격 기준**

- 위 순서에서 최종 결과는 `new.txt`만 남는다.
- 정렬 중 추가된 결과가 보존된다.
- 오래된 정렬 완료가 새로운 정렬 상태와 완료 알림을 덮어쓰지 않는다.
- 일반 정렬과 전역 정렬 모두 검증한다.
- 필터·현재 페이지·결과 합계·내보내기에 사용되는 목록이 일치한다.
- 오류/빈 목록/연속 초기화/역순 완료를 포함한다. 테스트는 임의 sleep 대신 작업 완료 순서를 제어한다.

### R02. 결과 수집 상한과 XML 검증 분리

관련 코드: [xml_search.rs](../src/rust_engine/src/xml_search.rs)의 `process_xml_attributes` 및 일반/존재 확인 경로.

**재현 입력**

```xml
<root><a>needle</a><b>needle</b><c x="needle" x="duplicate"/></root>
```

- `max_per_file=1`: 정상 매치 1개와 `__SF_TRUNCATED__` 반환.
- `max_per_file=10`: `ERR_XML_PARSE` 중복 속성 오류 반환.
- 직전 리뷰에서는 기본 상한 5,000과 정상 매치 5,001개를 사용한 경우에도 같은 현상을 확인했다.

현재 상한을 초과한 상태에서 속성 값이 매치되면 `return Ok(())`로 남은 속성 반복을 종료한다. 파서 이벤트 루프를 계속 돈다는 사실만으로 해당 속성들이 검증되는 것은 아니다.

**수정 방향**

- 모든 속성의 반복자 오류 확인과 값의 엔티티 해석은 계속 수행한다.
- 수집 상한 이후에는 검색어 비교·위치 탐색·경로 생성·결과 할당만 생략한다.
- 상한 초과 여부를 판정하기 위한 기존 추가 1건 수집 정책을 유지한다.
- 일반 검색과 존재 확인 모두 문서 종료까지 구문 검증한다. 사용자 취소는 기존 별도 정책을 유지한다.

**합격 기준**

- 상한 1/5,000 및 충분히 큰 상한에서 같은 손상 문서가 모두 구문 오류로 판정된다.
- Rust 일반 반환 API는 오류를 반환하고, 앱 검색 경로에서는 해당 문서의 정상 매치를 남기지 않고 `skipped`에 구문 오류를 표시한다.
- 상한 직전/직후의 중복 속성, 미정의 엔티티, 잘못된 속성 문법, 문서 끝의 불일치 태그를 확인한다.
- 정상 문서는 최대 N개 결과와 필요한 상한 안내를 유지한다.
- 수집 중단 이후 검증을 빠르게 하기 위해 파일 전체 유효성 검사를 생략하지 않는다.

### R03. XML 빈 요소 경로의 명시적 구성

관련 코드: [xml_search.rs](../src/rust_engine/src/xml_search.rs)의 Start/Empty 이벤트와 `process_xml_attributes`.

| 입력 | 기대 | 재검증된 실제 결과 |
|---|---|---|
| `<a><a x="needle"/></a>` | `/a/a/@x` | `/a/@x` |
| `<data><a x="needle"/></data>` | `/data/a/@x` | `/data/@x` |

**수정 방향**

- `ends_with(tag_name)`에 의한 문자열 추정을 제거한다.
- Start는 현재 요소가 포함된 경로를 사용하고, Empty는 부모 경로에 현재 요소를 명시적으로 추가한다.
- R06과 같은 경로 관리 코드를 수정하므로 정확성 테스트를 먼저 확정한 후 R06을 적용한다.

**합격 기준**

- 같은 이름 중첩, 이름의 접미사 일치, 루트 빈 요소, 형제 요소, 접두사가 있는 태그명, 한글 태그명을 검증한다.
- 빈 요소 다음 형제와 부모의 텍스트 경로에 이전 요소가 남지 않는다.
- 매치 개수와 값은 그대로이고 잘못됐던 경로만 교정된다.

### R04. XML 속성의 원본 위치 산출

관련 코드: [xml_search.rs](../src/rust_engine/src/xml_search.rs)의 `process_xml_attributes`, [lib.rs](../src/rust_engine/src/lib.rs)의 구조화 문서 디코딩, [result_view.py](../src/ui/result_view.py)의 행 기반 문맥 미리보기.

```xml
<root needle="other"
 x="needle"/>
```

- 기대: 속성 `x`의 값, 2행, 원본 UTF-8 바이트 offset 25.
- 실제: 속성 이름 `needle`의 위치인 1행, offset 6.

**영향 보정**

현재 문맥 미리보기는 주로 행 번호를 사용한다. 바이트 offset이 틀렸다는 이유만으로 모든 미리보기 동작이 잘못된다고 단정하지 않는다. 위 입력처럼 행 번호도 잘못되면 목록 위치와 문맥의 기준 행이 틀릴 수 있다.

**수정 방향**

- 값의 의미상 매치 판정은 기존 XML 파서의 디코딩된 값을 사용한다.
- 시작 태그 전체를 재검색하지 않고 현재 속성 값의 원본 범위 안에서 위치를 계산한다.
- 사용하는 quick-xml 버전의 실제 API를 확인해 원본 범위를 얻는다. 범위가 제공되지 않으면 이미 파싱된 속성 순서에 맞춘 단방향 커서를 검토한다. 전체 XML 파서를 별도로 구현하지 않는다.
- 엔티티 때문에 원본과 디코딩된 값의 정확한 매치 범위가 대응하지 않으면 `offset`/`length`는 없는 값으로 반환한다. 행 번호는 정확히 아는 범위에서 유지한다.
- UTF-8 BOM 보정은 한 번만 적용한다. Non-UTF8 XML은 UTF-8 변환 버퍼에서 검색하므로 그 offset을 원본 파일의 byte offset으로 오인하지 않게 한다. 원본 대응을 입증할 수 없으면 XML 결과의 바이트 위치를 생략한다.
- 위치 수정을 이유로 이미 검증된 매치를 삭제하지 않는다.

**합격 기준**

- 속성 이름에 검색어가 있는 경우, 여러 속성 값에 같은 검색어가 있는 경우, 여러 행에 걸친 속성, 작은따옴표/큰따옴표를 검사한다.
- 반환 offset이 있으면 원본 파일에서 해당 범위를 읽어 올바른 속성 값 내부인지 확인한다.
- 엔티티, 다중 바이트 문자, UTF-8 BOM, UTF-16 XML을 포함한다.
- 위치 탐색이 속성마다 시작 태그 전체를 반복 검색하는 구조가 되지 않는다.

### R05. Non-UTF8 청크 탐색 및 취소 응답성

관련 코드: [lib.rs](../src/rust_engine/src/lib.rs)의 `search_non_utf8_chunks`.

**재검증 실측**

줄바꿈 없는 UTF-16LE+BOM 파일에서 `absent` 검색, 각 크기 3회 중앙값:

| 크기 | 시간 |
|---|---:|
| 4MiB | 0.0056초 |
| 8MiB | 0.0174초 |
| 16MiB | 0.0509초 |

64MiB 단회 비교: 일반 검색 1.1017초, 시작 20ms 후 취소 요청 1.2722초. 후자의 증가량을 취소 기능의 고정 오버헤드라고 해석하지 않는다. 누적 재탐색 코드와 함께 보면 취소가 처리량을 충분히 줄이지 못한다는 근거다.

**수정 방향**

- 64KiB 입력 청크마다 취소 플래그를 확인한다.
- 다음 줄바꿈 탐색 시작 위치를 보관하고 이미 확인한 미완성 줄의 앞부분을 다시 탐색하지 않는다.
- 청크 안의 완성된 줄은 커서로 순회한 후 소비한 앞부분을 한 번에 정리한다. 줄마다 `drain()`하지 않는다.
- 줄바꿈과 매치가 청크 경계에 걸리는 경우, 디코더의 미완성 문자 상태, 마지막 입력 처리, CRLF, 마지막 개행 없는 줄을 보존한다.
- 기존 일반/정확 일치/존재 확인의 결과 의미와 개수 정책을 바꾸지 않는다.
- 이 단계는 재탐색·이동 비용과 취소 확인을 수정한다. 전체 줄을 보관하는 기존 특성을 바꾸거나 결과 문자열을 새로 잘라 메모리를 제한하는 작업은 포함하지 않는다.

**합격 기준**

- UTF-16LE/BE와 지원되는 EUC-KR 입력을 포함한 수정 전후 결과 비교.
- 청크 경계 직전/직후의 검색어, CRLF 분리, 한 글자 단위 짧은 줄, 긴 한 줄, 여러 긴 줄을 검사한다.
- 4/8/16/32/64MiB 크기별 추이를 비교해 반복 재탐색이 제거됐는지 확인한다.
- 취소 시 부분 결과 정책을 확인한다. 전체 호출의 디스크 읽기/스냅샷 생성까지 무조건 즉시 취소된다고 보장하지 않는다.
- 파서 내부 취소는 결정적인 플래그/청크 테스트로 검증하고, Python 이벤트와 GIL 종료 경로는 제한 시간 있는 별도 프로세스로 검증한다.

### R06. 깊은 XML 경로 생성 비용 개선

관련 코드: [xml_search.rs](../src/rust_engine/src/xml_search.rs)의 경로 캐시.

**재검증 실측**

`<a>`를 지정 깊이만큼 연 후 닫은 정상 문서에서 무매치 검색, 각 3회 중앙값:

| 깊이 | 파일 크기 | 시간 |
|---|---:|---:|
| 2,000 | 14KB | 0.0058초 |
| 4,000 | 28KB | 0.0209초 |
| 8,000 | 56KB | 0.0838초 |

**수정 방향**

- 하나의 경로 문자열과 각 깊이의 이전 바이트 길이를 보관한다.
- Start에서 태그를 append하고, End에서 기록된 길이로 truncate한다.
- Empty 경로는 R03에서 확정한 동작에 따라 임시로 구성한 후 복원한다.
- UTF-8 문자 경계가 보장된 길이만 사용한다.
- 매치 결과에 필요한 경로 복사 비용은 유지한다. 매치마다 긴 경로를 출력하는 경우까지 전체 실행 시간이 항상 선형이라고 주장하지 않는다.

**합격 기준**

- R03의 경로 정확성 테스트 전체 통과.
- 깊은 무매치·깊은 단일 매치·얕고 넓은 문서·많은 매치·상한 도달·존재 확인·손상 XML을 검사한다.
- 무매치 경로 관리에서 깊이 증가에 따른 제곱 수준 비용을 제거한다.
- 새로운 깊이 제한이나 스킵 정책을 도입해 빠르게 보이도록 만들지 않는다.

### R07. 빌드 시 프로세스 종료 제거

관련 코드: [build_rust.py](../build_rust.py)의 `unlock_file_windows`, `build_rust_engine`.

현재 엔진 파일을 잠근 프로세스가 빌드 자신의 PID가 아니면 종료한다. 해당 빌드가 생성한 프로세스인지 확인하는 조건이 없다. 검증된 위험은 개발·빌드 작업에서의 다른 프로세스 미저장 데이터 손실이다.

**수정 방향**

- 엔진 파일 교체를 위해 임의의 프로세스를 종료하는 동작을 제거한다.
- 잠긴 파일을 안전하게 교체할 수 없다면 빌드를 실패로 종료하고 대상 파일과 필요한 조치를 표시한다.
- 엔진 복사·교체 실패를 성공으로 표시하지 않는다. 사용 가능한 기존 엔진을 먼저 삭제하지 않도록 임시 산출물과 교체 순서를 점검한다.
- 실행 중인 앱을 자동 종료하는 별도 기능은 추가하지 않는다.
- 기존 배포 EXE와 엔진의 처리 순서를 확인하고, 빌드 실패 시 남는 산출물의 상태를 명확히 한다.

**합격 기준**

- 잠금 없음/접근 거부/다른 Python 프로세스가 사용 중인 상황을 모킹한다.
- 다른 프로세스의 `terminate()`/`kill()`이 호출되지 않는다.
- 실패 시 기존 파일 보존과 실패 코드 반환을 검증한다.
- 정상 빌드는 새 엔진 및 EXE 내부 엔진의 버전·해시가 일치한다.
- 실제 사용자 프로세스를 종료하는 테스트를 실행하지 않는다.

### R08. 최소 범위 코드 정리

관련 코드: [lib.rs](../src/rust_engine/src/lib.rs), [types.rs](../src/rust_engine/src/types.rs), [xml_search.rs](../src/rust_engine/src/xml_search.rs).

**수정 방향**

- `InternalSearchParams.pat_bytes`와 사용되지 않는 생성·전달·복제를 제거한다. 현재는 최종 소비 함수에서 `_pat_bytes`로 버린다. 검색용 Aho-Corasick 패턴은 유지한다.
- 중복 `RawMatch` 별칭을 공통 정의 하나로 통일한다.
- XML 모듈의 `#![allow(dead_code)]`를 제거한 후 실제 경고를 확인한다. 공개 API/테스트에서 필요한 코드인지 검토한 뒤 불필요한 코드만 정리한다.
- `lib.rs` 첫 줄의 전역 allow 설명 및 “라인당 한 번 FFI 호출” 주석을 실제 동작에 맞춘다.
- XML 경로 캐시 주석은 R06 결과에 맞춰 갱신한다.
- 광범위한 클래스 분리, 변수명 일괄 변경, 설정 스냅샷 정책 변경은 포함하지 않는다. 스냅샷 복사는 외부 변경 방어 역할이 있으므로 미사용 코드로 취급하지 않는다.

**합격 기준**

- 폐기한 필드의 참조가 없어야 한다.
- Rust 포맷·테스트·Clippy 통과, 검색 결과 계약 유지.
- 이 변경의 성능 효과를 별도 실측 없이 체감 개선이라고 주장하지 않는다.

## 6. 후속 구현 및 검증 기록 (2026-09-07)

### 반영 내용

- R01: 정렬 요청 번호·데이터 리비전 검증, 실패 시 결과 보존, 대기 중인 최신 정렬 재실행을 공통 워커로 구현했다. 이전 작업과 새 작업의 완료 순서를 양방향으로 통제하는 회귀 테스트를 추가했다.
- R02: 결과 수집 상한 이후에도 속성 검증을 계속한다. 추가 확인된 존재 여부 경로의 첫 속성 매치 뒤 검증 누락도 수정했다. 중복 속성·잘못된 엔터티·깨진 속성에 대해 오류 반환 및 앱 검색의 빈 결과/스킵을 검증했다.
- R03/R06: 경로를 증분 추가하고 이전 바이트 길이로 복원한다. 동일 이름·접미사 이름·한글 태그 및 빈 요소 이후 부모 경로를 검증했다.
- R04: 매치된 속성 값의 원본 범위로 행·위치를 계산한다. BOM/여러 줄/동일 문자열 반복을 검증하고, 엔터티 변환 및 비UTF-8 디코딩으로 신뢰할 수 없는 바이트 위치는 생략한다.
- R05: 개행 검색 시작점을 유지하고 청크당 한 번만 접두부를 제거한다. 청크마다 취소를 확인한다. UTF-16 LE/BE·EUC-KR의 청크 경계, CRLF, 긴 줄, 마지막 줄, 정확/부분/존재 검색 및 취소 시 기존 결과 보존을 검증했다.
- R07: 외부 프로세스 강제 종료 코드를 제거했다. 같은 디렉터리의 임시 파일에서 교체하며 복사·교체 실패 시 기존 바이너리를 보존한다. EXE는 `build/release`에서 생성한 후 성공 시 교체한다. 복사 실패·잠금 실패·정상 교체 회귀 테스트를 추가했다.
- R08: `pat_bytes` 전달·할당·복제와 중복 `RawMatch` 별칭을 제거하고 공통 타입을 사용한다. XML의 포괄적 dead-code 허용 및 실제와 다른 주석을 정리했다.

### 검증

- 수정 전 정렬 재현 테스트 4개와 XML 재현 테스트 3개가 실패하는 것을 확인한 뒤 수정했다.
- 새 Rust 엔진 release 빌드 성공. Rust 단위 테스트 42개 통과, `cargo fmt --check` 및 Clippy 경고 없음.
- Python 전체 테스트 381개 통과, 기존 1개 스킵·10개 선택 제외. 기본 OS 임시 경로의 접근 권한 오류는 프로젝트 내부 `--basetemp .test_remediation_full` 지정으로 해결했다. 이후 추가한 완료 역순 테스트까지 최종 실행 결과는 아래에 기록한다.
- Ruff 및 mypy 통과. 기존 손상 XML/JSON, Excel 수식 텍스트 내보내기, JSON boolean, 검색 제한·취소·단일 파일 종료 회귀 테스트 포함.
- A–J 벤치마크: 예상 매치 합계 159건, 스킵 0건, 기존 성능 임계값 통과. `benchmark_history.md`의 `v5.9.2-review`로 기록했으며 정식 버전 변경을 의미하지 않는다.
- PyInstaller 패키징 성공. 최종 설치 대상만 검증용 `.validation_release/StringFinder.exe`로 바꿔 실행하고 배포 경로는 보존했다. 정식 배포는 수행하지 않았다.

| JSON 희소 매치 | 0.0649 | 0.0400 | 0.0400~0.0401 |
| JSON 존재 확인 | 0.0938 | 0.0292 | 0.0284~0.0294 |
| JSON 무매치 폴백 | 0.2464 | 0.2498 | 0.2493~0.2539 |
| XML 스트리밍 | 0.0976 | 0.0956 | 0.0950~0.0956 |

반복 비교에서 10% 및 2ms를 모두 넘는 악화는 없었다. JSON 스트리밍 구현 자체는 이번 수정 대상이 아니므로 큰 시간 감소를 이번 코드 정리의 인과적 효과로 주장하지 않는다. 호출 환경·빌드 차이에도 영향을 받는 절대값이며, 버전 간 보장 성능이 아니다. 수정 후 측정된 RSS 증가량의 전체 최대는 1.59MiB(수정 전 1.63MiB)였고, 이는 전후 RSS 차이이지 순간 최고 메모리가 아니다.

### 경계 입력 성능 및 남은 한계

재실행 도구 `python tools/benchmark_review_edges.py`를 추가했다. 무매치 깊은 XML(2천/4천/8천 깊이), 개행 없는 UTF-16(4/8/16/64MiB), 20ms 뒤 취소 요청을 측정한다. 입력 생성 제외, 준비 실행 1회 및 측정 3회 중앙값이다.

첫 수정 후 측정에서 XML은 0.284/0.712/0.709ms, UTF-16은 2.930/6.981/11.538/52.891ms였으며, 64MiB 취소는 호출 시작부터 46.989ms였다. 작은 XML 시간은 스케줄링 변동 비중이 크므로 단조 증가를 요구하지 않는다. 최초 재검증 당시 8천 깊이 83.8ms, UTF-16 16MiB 50.9ms 및 64MiB 취소 1.2722초와 비교하면 병목 제거 방향이 확인되지만, 재현 스크립트를 영구화하기 전의 참고 측정과 엄밀한 동일 실행 조건 비교는 구분한다.

- 긴 한 줄은 여전히 전체 디코딩 줄을 보관한다. 이번 변경은 줄 길이 제한이나 결과 축약을 도입하지 않았다.
- 파일 스냅샷 I/O 및 감시 스레드 폴링은 즉시 취소를 보장하지 않는다. 취소 확인 간격 개선이 모든 입력의 응답 시간 상한을 보장하지 않는다.
- 구조 문서의 후반부 오류 검증을 생략하거나 메모리·결과 제한을 완화하지 않았다.
- 배포 EXE 및 버전은 그대로 유지한다. 개발용 엔진만 새 코드로 빌드했으며 커밋하지 않았다.

### 최종 재확인

- 패키징 과정에서 다시 빌드된 최종 엔진으로 Python **383개 통과**, 1개 스킵·10개 선택 제외를 확인했다. 신규 회귀 테스트는 총 15개다.
- 검증 EXE에 포함된 엔진은 개발용 엔진과 바이트 단위로 동일했다. 엔진 SHA-256: `bb88f6000c70c148f534f565aa5118b97704d9434e817532b3326c5332e0ca5d`. 기존 배포 EXE SHA-256은 `768875f52f3549d458d671edd68c7fbe6c36c35bf71d00019eec93ab1690226f`로 보존됐다. 기존 배포본과 검증본 모두 엔진이 루트 및 `rust_engine` 경로에 포함되며, 검증본의 두 항목은 동일했다.
- 최종 엔진의 대표 벤치마크도 독립 프로세스 3회 재측정했다. 위 표 순서대로 중앙값은 0.0086 / 0.0091 / 0.0088 / 0.0414 / 0.0404 / 0.0293 / 0.2473 / 0.0950초다. 동일 회귀 조사 기준을 넘는 악화는 없었다. RSS 차이 최대는 2.76MiB로, 실행 사이 메모리 할당 변동이 있으므로 이전 1.59MiB를 상한으로 해석하지 않는다.
- 최종 경계 벤치마크: XML 2천/4천/8천 깊이 0.315/0.453/0.696ms, UTF-16 4/8/16/64MiB 2.390/4.555/9.366/44.859ms, 64MiB 취소 41.944ms. 측정 범위에서는 개선이 유지됐다.
- 검증용 임시 파일 및 별도 EXE는 확인 후 정리한다. 정식 배포본 교체·버전 변경·커밋은 수행하지 않는다.
