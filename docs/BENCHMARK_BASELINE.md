# 벤치마크 기준선 (v7.1.1)

7.1.1부터의 성능 비교 기준입니다. 6.x의 기준·측정 기록은 [v7 이전 기록](archive/before-v7/README.md)에 있습니다.

## 1. 무엇을 재는가

- **엔진의 폴더 검색 시간**(`sf_engine.search_dir`)을 잽니다. 앱의 결과 정리·화면 갱신·세션 저장은 포함하지 않습니다.
- 도구는 `tools/benchmark.py` 하나입니다. 표본 만들기·측정·비교 명령은 [개발자 가이드 7.3절](DEVELOPER_GUIDE.md#73-벤치마크와-릴리스-검증)에 있습니다.
- 기준값 원본은 [`benchmark_baseline.json`](benchmark_baseline.json)입니다. 도구는 이 파일과 비교합니다.

## 4. 판정 규칙

`python tools/benchmark.py run`이 표본마다 다음을 판정하고, 하나라도 걸리면 종료 코드 1을 돌려줍니다.

| 표시 | 조건 | 뜻 |
| --- | --- | --- |
| 결과 다름 | 일치 수 또는 결과 지문이 기준선과 다름 | 찾은 줄·내용·건너뛴 파일이 바뀜. 의도한 변경인지 먼저 확인 |
| 느려짐 | 중앙값이 기준선의 1.15배 초과 | 같은 장비에서 다시 재서 반복되면 회귀로 봄 |

- A(작은 파일 1만 개)·C(바이너리 섞인 폴더)·S-ascii-cap(수 ms)은 회차 사이 흔들림이 ±10% 안팎입니다. 이 표본만 1.15배를 조금 넘으면 다시 잽니다.
- 다른 장비에서는 시간을 비교하지 않습니다. 결과 지문만 비교합니다.
- 기준선은 안정 버전을 선언할 때만 `--write-baseline`으로 바꾸고, 바꾼 이유를 [성능 기록](PERFORMANCE_HISTORY.md)에 적습니다.

## 5. 6.4.1과의 관계

7.1.1(=6.4.20 코드)은 6.4.1 엔진과 번갈아 잰 마지막 측정에서 모든 공통 표본이 0.38~1.03배였습니다. 한글 검색어·CP949·UTF-16·구조화 파일 값 검색이 약 2~2.5배 빠릅니다. 자세한 표는 [v7 이전 성능 기록 16절](archive/before-v7/PERFORMANCE_HISTORY.md)에 있습니다.
