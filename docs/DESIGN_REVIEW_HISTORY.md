# StringFinder 설계 검토 기록

정리일: **2026-10-21**. 반려·취소·보류한 접근과 이유를 기록합니다. 채택한 설계는 [개발자 가이드](DEVELOPER_GUIDE.md#5-현재-설계로-이어진-결정), 현재 계약은 [구현 정책](IMPLEMENTATION_POLICY.md)에 있습니다.

## 1. 상태와 판단

**미채택**은 검토했지만 최종 구현에 넣지 않은 방식, **보류**는 근거 부족 또는 작업 중단 상태, **제거**는 적용했던 기능을 없앤 상태입니다. 보류를 효과 없음으로 해석하지 않습니다.

### CUDA 도입 보류의 근거와 범위

현재 검색은 파일 탐색·읽기, 인코딩 해석, JSON/XML 검증, Excel 압축 해제·셀 값 변환과 문자열 비교로 구성됩니다. 문자열 비교를 GPU로 옮겨도 나머지 비용은 남으며, CPU↔GPU 데이터 전송·실행·결과 회수와 GPU 메모리 예산, 비 NVIDIA 환경의 CPU 대체 경로를 추가로 관리해야 합니다. 현재는 이런 구현·검증 부담을 정당화할 전체 검색 시간의 개선 근거가 없어 도입을 보류합니다.

판단의 한계는 다음과 같습니다.

- [6.1.1 기준선](ENGINE_PERFORMANCE_BASELINE.md)의 Set A 중앙값은 0.735초이지만, 파일 접근·비교 등 비용을 분리한 값이 아닙니다. 이를 OS 호출만의 병목이나 GPU 가속 불가능의 증거로 사용하지 않습니다.
- CUDA 초기화·전송 비용은 장비·데이터 크기·컨텍스트 재사용 여부에 따라 달라집니다. 현재 GPU 측정값이 없으므로 B–J 실행 시간보다 반드시 크다고 단정하지 않습니다.
- 구조 파서의 상태 추적과 무결성 검증은 현재 CPU 구현을 GPU로 그대로 옮기기 어렵게 만드는 요소이지, GPU에서 무결성을 지킬 수 없다는 뜻은 아닙니다. 배포본 크기 증가량도 포함 라이브러리와 배포 방식 없이 확정하지 않습니다.

재검토는 대용량 데이터를 메모리에 유지한 반복·다중 패턴 검색 등에서 **문자열 비교가 전체 시간의 주요 비중임이 확인될 때** 진행합니다. 파일 준비부터 전송·검색·결과 회수까지 포함한 CPU/GPU 교대 측정으로 전체 이득을 확인하고, 파일 집합·결과 내용·위치·인코딩·부분 실패·취소·메모리 보호 계약과 CPU 대체 경로를 함께 검증해야 합니다. 원문 바이트의 GPU 사전 검색으로 Unicode 정규화나 구조화 값 변환 후의 일치를 누락시키는 최적화는 허용하지 않습니다.

참고: [NVIDIA 공식 지침 — CPU↔GPU 전송 비용 최소화](https://docs.nvidia.com/cuda/cuda-c-best-practices-guide/index.html#data-transfer-between-host-and-device). 이 자료는 일반적인 설계 지침이며 StringFinder의 GPU 성능 측정 결과가 아닙니다.

## 2. 근거가 제한적인 과거 후보

| 후보 | 현재 상태와 재검토 시 주의점 |
| --- | --- |
| XLSX 압축 파일 메모리 예산·네이티브 후보 | 과거 실험 기록이며 제품 기본 최적화로 채택되지 않았습니다. 속도뿐 아니라 메모리·손상 입력·취소를 함께 비교해야 합니다. |
| 동일 파일 핸들 재사용·Calamine 입력 경로 | 검토 기록은 있지만 확인 가능한 채택 근거·개선 수치가 없어 효과를 단정하지 않습니다. |
| 소형 XML 묶음 처리 | XML 특수 검색의 파일별 반복 비용을 줄일 후보로 논의했으나 최적화 작업을 중단했습니다. 일반 텍스트 검색과 혼동하지 않으며 적용 완료로 기록하지 않습니다. |

스킵 사유 모듈 분리와 리소스·손상 파일 QA는 유지보수·신뢰도 작업입니다. 측정을 수행했다는 이유만으로 검색 속도 최적화로 분류하지 않습니다. 관련 일반 변경은 개발 이력과 개발자 가이드에서 확인합니다.


## 3. 기록 규칙

접근 → 상태 → 검토/적용 버전 또는 작업본 → 이유와 근거 → 현재 대안 → 재검토 조건을 기록합니다. 이유가 확인되지 않으면 **근거 미확인**으로 남깁니다. 과거 XLSX 후보 보류와 6.0.3 공개 셀 API 채택처럼 다른 접근과 적용 시점을 구분합니다.
