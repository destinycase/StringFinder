# StringFinder 버전별 개발 히스토리

## v6.3.2 · 검색 설정 이름과 화면 안내 개선

- **목적:** ‘누락 방지’가 항상 더 좋은 검색이라는 오해를 줄이기 위해 메뉴를 ‘기본 검색 (권장)’·‘글자 변형 검색 (느림)’으로 바꿨습니다. 후자는 기본 검색으로 예상한 글자를 찾지 못했을 때 좁은 범위에서 사용하는 보조 방식이며 모든 인코딩 문제를 해결하지는 않습니다.
- **화면:** ‘특수 검색’을 ‘값만 검색’으로 바꾸고 JSON·XML·Excel 항목을 간결하게 표시합니다. 검색 설정 라벨을 버튼 왼쪽에 추가하고 좁은 창에서는 라벨 폭을 맞춘 두 줄 배치로 전환합니다. 버튼은 조합별로 폭이 변하지 않으며 꺼진 값 검색은 생략하고 느림 표시는 유지합니다. 접근성 이름에는 두 설정을 모두 제공합니다.
- **유지:** 엔진 검색·파일 선별·결과·제한은 바꾸지 않았습니다. 기존 형식별 저장 문자열과 검색 모드 불리언을 유지하고 표시 문자열만 분리했습니다. 이전 세션 복원, 검색 전달값과 한글·영문 안내를 검증합니다. 과거 측정값과 6.1.1 기준선은 보존합니다.
- **검증:** 기본 Python 테스트 1,250개 통과·2개 건너뜀·16개 제외, Rust 67개 통과. 최종 안내 문구 정리 후 메뉴·현지화 152개도 통과했습니다. Ruff와 제품·진단 도구 mypy 40개 파일이 통과했습니다. 두 언어의 전체 14개 선택 조합, 이전 한글·영문 저장값 복원, 고정 폭·접근성 연결을 검사하고 100%·150% 배율의 600·720·1280 폭 화면을 확인했습니다. 기존 윤초 경고 4건은 유지됩니다.
- **배포:** 교체된 EXE의 프로젝트 소스·단일 Rust 엔진·버전/API·Qt ICU·격리 실행 검증을 통과했습니다. EXE는 72,876,255바이트이며 SHA-256은 `0dd0b96f74eca8d2bae5cffad8f85230233c658a02ba039fe3fd1e67171ef181`입니다. 압축 파일 없이 로컬 배포·커밋하며 푸시는 하지 않습니다.

## v6.3.1 · 검색 개선과 회귀 검증 통합 릴리스

- **통합 범위:** 6.2.3의 손상 UTF-8 정확 일치 오탐 수정, Windows 일반 텍스트 파일 정보 재사용, 결과 전달 종료 대기 감소와 ASCII 정확 일치 최적화를 통합합니다. 종료 대기 회귀 검사의 적중 1개·무결과 300개 표본 보완도 포함합니다. Python 앱·패키지·Rust 엔진과 공개 문서의 현재 기준을 6.3.1로 맞췄습니다.
- **유지한 판단:** 누락 방지 ASCII 사전 판정과 다중 루트 통합은 보류 상태를 유지합니다. 검색 조건·설정 기본값·제한·검색 결과 형식은 추가로 변경하지 않았습니다. 기존 측정 이력과 6.1.1 성능 기준선을 보존하며, 이번 통합 버전 이름으로 과거 측정값을 다시 표시하지 않습니다. D 전체 검색의 기존 메모리 기준 초과 기록도 유지합니다.
- **검증:** 새 배포 엔진으로 기본 Python 1,192개 통과·2개 건너뜀·16개 제외, 별도 stress/chaos 10개와 Rust 67개를 통과했습니다. 보완된 종료 대기 검사 4개 조합도 포함합니다. 제품·진단 도구 mypy 40개 파일, Ruff·Clippy·Rust 포맷·변경 diff 검사를 통과했습니다. 기존 윤초 변환 경고 4건은 유지됩니다.
- **배포:** 프로젝트 소스 일치·Rust 엔진 단일 포함·Python/패키지/Rust/EXE 버전과 API 일치·Qt ICU·교체된 EXE 격리 실행 검증을 통과했습니다. `dist/StringFinder.exe`는 72,874,471바이트이며 SHA-256은 `3982f7a9f5ec22ed4aceaefad3224de04f35f96d6cc732484fc4d1a0ca4ebebc`, 엔진 SHA-256은 `61470eb647ffa4969fd64b0fd44d204d9dffdf17094107014d053c53e2f02fd5`입니다. 실행 파일만 교체하고 압축 배포 파일은 생성하지 않았습니다. 로컬 작업 지침과 내부 검증 자료는 포함하지 않았습니다.

## v6.2.3 · 검색 오탐 수정과 검증된 일반 검색 최적화

- **후속 · 결과 전달 종료 대기 회귀 검사와 적중 표본 보완:** 폴더·파일 목록 API × 적중·무결과의 4개 조합에 결과 콜백과 대기 설정 1,000ms를 적용합니다. 적중 표본은 1개와 무결과 파일 300개로 구성하고 파일 목록의 맨 앞에 적중 파일을 둡니다. 첫 결과를 전달한 뒤에도 확인할 파일이 남아 있어야, 잠시 기다리던 결과 전달 스레드를 즉시 깨우는 동작을 시험할 수 있기 때문입니다. 이 표본으로 기존의 파일 목록 적중 조합이 구형 엔진에서도 빠르게 종료해 통과하던 한계를 해소했습니다. 무결과 표본은 기존 구성을 유지하며 적중이 정확히 1건인지, 내용·위치·건너뛴 파일이 콜백 없는 검색과 같은지 확인합니다. 준비 실행 1회 후 5회 최솟값 500ms 미만 기준을 유지해 정상 종료와 과거 약 1,000ms 대기를 구분하면서 일시적인 장비 지연에 여유를 둡니다. 별도 프로세스·20초 제한·12초 진단 덤프도 유지합니다. 현재 엔진 4개 조합은 모두 통과했고 저장한 6.2.2 엔진(`6aae3022…`)은 3회 반복마다 4개 모두 실패했으며, 60개 측정값 중 500ms 미만은 없었습니다. 전체 기본 Python 1,192개 통과·2개 건너뜀·16개 제외, mypy 40개 파일과 Ruff가 통과했습니다. 제품 코드·대기 기본값·D 메모리 기준·다른 테스트·버전·배포본은 변경하지 않았으며 로컬 커밋까지만 수행합니다.
- **무결성:** 잘못된 UTF-8 줄을 내부 대체 문자열 `INVALID_UTF8`과 비교해 생기던 정확 일치 오탐을 수정했습니다. 정상 문자열은 검색하고 손상된 줄은 해당 문자열로 일치하지 않도록 단일 파일·폴더·파일 목록 API에서 검증했습니다.
- **적용 범위:** Windows 일반 텍스트 순회에서 보관된 파일 정보를 재사용합니다. 크기 초과로 보이면 현재 정보를 다시 확인하고, 파일을 연 뒤의 최종 크기·숨김 검사는 유지합니다. 구조 문서·Excel·정션의 최신 정보 조회와 메모리 예약은 변경하지 않았습니다. 결과 전달 스레드는 생산 작업 완료 후 모든 송신자를 닫아 즉시 깨우며 마지막 배치·중지 시 큐·콜백 오류를 보존합니다. ASCII 정확 일치는 기존 공백 제거와 정규화된 검색어 비교를 유지하며 중간 문자열 생성을 줄였습니다.
- **보류:** 다중 루트 통합 순회는 중지·전체 상한 시 결과 순서 영향 때문에 보류하고 문서를 실제 루트별 순회에 맞췄습니다. 누락 방지 ASCII 사전 판정은 무결성 검사를 통과했지만 적중 표본이 약 2.7% 느려져 실험 코드를 제품에서 제외했습니다. 누락 방지 검색 정책과 구현은 유지합니다.
- **검증:** 기본 Python 1,188개 통과·2개 건너뜀·16개 제외, 확장 stress/chaos 10개 및 Rust 67개 통과. 제품·진단 도구 mypy 40개 파일, Ruff·Clippy·Rust 포맷 검사를 통과했습니다. 기존 엔진과 521개 파일 × 13개 검색어의 공개 API 결과·위치·건너뛴 안내 대조 6,773개 조합에서 불일치는 없었습니다. 손상 UTF-8 오탐은 별도 재현·수정 검증으로 구분합니다.
- **성능:** 같은 장비·같은 표본에서 준비 실행 후 15회 교대 측정했습니다. 네이티브 A 세트는 842.4→470.8ms(-44.1%), 콜백을 끈 소형 파일 전용 비교도 -42.9%, ASCII 정확 일치 전용 표본은 63.56→7.09ms(-88.8%)였습니다. 이는 해당 호출·표본의 결과이며 모든 검색의 개선율이 아닙니다. 워커 A–J 측정 5회 모두 결과 159건·건너뛴 파일 0건이며 D를 제외한 공식 임계값을 통과했습니다. D 500MiB 전체 검색의 기존 RSS 150MiB 기준은 이전 엔진도 초과했습니다(이전 최대 542.0MiB, 현재 최대 540.1MiB). 기준을 완화하거나 실패를 통과로 바꾸지 않았으며 상세 비교는 성능 개선 기록에 남깁니다. 6.1.1 공식 기준선은 유지합니다.
- **로컬 배포:** 프로젝트 소스 일치·Rust 엔진 단일 포함·버전/API·Qt ICU·교체된 EXE 격리 실행 검증을 통과했습니다. EXE는 72,876,912바이트, SHA-256은 `5c894a7e703ea0b81c28db3528c2430b4950ee8f53173b1c3be5df8161e01bab`이며 재빌드된 배포 엔진 SHA-256은 `f8b70e0424d96bc140f0f1597d84271f10d919b519050cf95aa2bb727053cd5a`입니다. 압축 배포 파일은 만들지 않았습니다. 사용자 지시에 따라 로컬 커밋까지만 수행하고 푸시하지 않습니다.

## v6.2.2 · Windows 자동 검사와 타입·테스트 체계 정비

- **후속 · 검색 속도 제안 검토:** 중복 파일 정보 조회·결과 전달 종료 대기·다중 루트 순회·ASCII 비교 및 사전 판정 후보를 현재 코드와 의존 라이브러리에 대조했습니다. 현행 엔진의 소형 무결과 검색에서 콜백 대기 설정에 따른 종료 지연을 확인했으며, 제안서의 모의 측정 개선율을 제품 개선율로 확정하지 않았습니다. 잘못된 UTF-8 줄이 `invalid_utf8` 정확 일치 결과로 포함되는 조건부 오탐도 재현해 별도 수정 후보로 기록했습니다. 상세 근거는 내부 검토 자료에 보존하며 제품 코드·버전·배포본은 변경하지 않았습니다.
- **후속 · 진단 도구 타입 정리 재배포:** 사용자 요청에 따라 버전 6.2.2를 유지하고 최신 진단 도구를 포함한 실행 파일을 교체했습니다. 전체 검사 중 설정 저장 실패 주입이 다른 설정 관리자의 지연 저장까지 가로채는 테스트 간 간섭을 확인해, 실패 주입을 해당 테스트의 파일로 한정했습니다. 수정 후 기본 Python 1,179개 통과·2개 건너뜀·16개 제외, Rust 64개, 제품·진단 도구 mypy 40개 파일과 Ruff가 통과했습니다. 기존 윤초 변환 경고 4건은 유지됩니다. 프로젝트 소스 일치·엔진 단일 포함·Qt ICU·교체된 EXE 격리 실행 검증도 통과했습니다. EXE는 72,875,461바이트, SHA-256은 `d953ab51012eddf89d63fd97c3d3edef37bbbb1854b6f3a408828ea852d0f4fc`이며 Rust 엔진은 기존과 동일합니다. 압축 파일은 생성하지 않았습니다.
- **후속 · 진단 도구 타입 검사 완료:** 진단 도구에 남았던 타입 오류 66건을 보고서·파일별 집계·실행 결과·취소 신호의 자료형을 명시해 해결했습니다. 도구를 가져올 때 검사를 분리하던 설정은 제거하고 CI 검사 대상에 진단 도구를 명시했습니다. 제품과 진단 도구 40개 파일의 mypy 및 Ruff가 통과했습니다. 관련 테스트 48개와 수정 전·후 정상 완료·시간 초과·취소 보고서 대조를 통과했으며, JSON 값과 Markdown 내용은 유지됩니다. 검증 도구·테스트·문서 정리로 버전과 배포본은 유지합니다. 아래의 66건 잔여 표기는 최초 작업 당시 상태입니다.
- **범위와 정책:** 외부 제안 중 대형 클래스·함수 분할(WO-5)은 제외했습니다. 소유자 선택에 따라 EXE·엔진의 Git 보관과 작업별 버전·배포 규칙은 유지합니다. 검색 비교·후보 선별·제한값·결과 형식은 바꾸지 않았습니다.
- **자동 검사:** main 푸시·PR 및 주간·수동 실행용 Windows 워크플로를 추가했습니다. Python 3.12·Rust 1.93.0과 기준 라이브러리 버전을 사용하고, 현재 소스로 만든 네이티브 엔진의 경로·버전·API를 먼저 확인합니다. Ruff·제품 mypy·Rust 포맷/Clippy/테스트와 Python 기본 검사를 실행하며 주간·수동 실행은 stress/chaos와 실제 Windows 클립보드 연동을 추가합니다. 읽기 권한과 pip/Cargo 캐시를 사용하며 자동 배포·이력 재작성은 하지 않습니다. 원격 실행 결과는 해당 Actions 실행 기록에서 확인합니다.

## 문서 안내

이 문서는 날짜가 아닌 버전 단위로 Git 커밋과 당시 문서를 추적해 정리한 기록입니다. 버전별 내용은 커밋 메시지와 실제 변경 파일을 대조해 작성했으며, 기능을 명시한 근거가 없는 초기 버전은 확인 가능한 범위만 기록했습니다.

현재 설계와 준수 계약은 [개발자 가이드](DEVELOPER_GUIDE.md#5-현재-설계로-이어진-결정)와 [구현 정책](IMPLEMENTATION_POLICY.md)에 있습니다. 이 문서는 적용 버전·변경·검증·배포 사실을 기록합니다.

최신 버전부터 역순으로 표시합니다. 여러 버전을 묶은 항목도 높은 버전부터 표기하며, 같은 버전의 후속 기록은 기존 순서를 유지합니다.

## 이력 검증 방법

특정 버전의 실제 변경을 재확인하려면 다음 명령을 사용합니다.

```powershell
git show --stat <커밋>
git show <커밋> -- <파일>
git diff <이전 커밋>..<현재 커밋> -- <파일>
```

초기 버전처럼 커밋 메시지가 단순한 경우에는 해당 커밋의 파일 스냅샷과 다음 버전의 차이를 함께 확인해야 하며, 이 문서의 요약을 세부 API 계약으로 사용해서는 안 됩니다.
