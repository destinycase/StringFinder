# StringFinder 버전별 개발 히스토리

7.1.1부터 새로 기록합니다. 6.4.20까지의 이력은 [v7 이전 개발 히스토리](archive/before-v7/DEVELOPMENT_HISTORY.md)에 있습니다.

## v7.1.1 · 2차 안정 버전 (Rust 단일 엔진)

7.1.1을 두 번째 안정 버전으로 지정합니다(2026-11-13). 코드는 6.4.20과 같고, 버전 번호와 기록 체계만 새로 시작합니다. 고정 문서는 [master-baseline-v7.1.1.md](master-baseline-v7.1.1.md)입니다.

1차 안정 버전 6.4.1 이후 바뀐 주요 내용은 다음과 같습니다. 버전별 세부는 보관된 이력을 보세요.

- **검색 엔진 하나로 통합:** 모든 검색을 Rust 엔진 하나로 합니다. 예전의 "글자 변형 검색"(Python, 느림)과 검색 방식 선택이 없어졌고, 기본 검색이 그 비교를 모두 합니다. 대상은 대소문자 전체 규칙(`Straße` = `strasse`), 분해형 한글(NFD), CP949·UTF-16 파일, JSON·XML·Excel·UE archive 값입니다.
- **속도:** 6.4.1보다 한글 검색어는 최대 약 2.6배, CP949 파일은 약 2배, UTF-16 파일은 약 1.3~1.7배, 구조화 파일 값 검색은 항목에 따라 약 1.1~2.3배 빨라졌습니다. 바이너리가 많은 폴더의 한글 검색, 일치가 아주 많은 검색의 결과 정리도 빨라졌습니다.
- **검색 모드 선택:** 검색줄 왼쪽 콤보 박스에서 기본·JSON·XML·Excel·archive 값만 검색을 고릅니다.
- **필터 표시:** 확장자·파일명 필터를 탭이나 위아래로 함께 볼 수 있습니다(기본은 탭).
- **정확성:** 일부를 해석하지 못한 파일은 안내로 알립니다. 정확히 일치 검색은 검색어 앞뒤 공백을 무시합니다. JSON 키의 `/`는 중첩 경로와 구분해 보여 줍니다. 상세 목록의 강조가 검색과 같은 기준을 씁니다.
- **화면·안정성:** 검색 종료 후 저장을 백그라운드에서 해 화면이 멈추지 않습니다. 정렬 순서가 실행마다 바뀌지 않습니다. 전체 결과 상한에 닿으면 엔진이 바로 멈춥니다. 탭 이름 중복, 데이터 삭제 후 재저장, Excel 저장 실패 같은 문제를 고쳤습니다.
