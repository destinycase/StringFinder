# StringFinder 버전별 개발 히스토리

이 문서는 날짜가 아닌 버전 단위로 Git 커밋과 당시 문서를 추적해 정리한 기록입니다. 버전별 내용은 커밋 메시지와 실제 변경 파일을 대조해 작성했으며, 기능을 명시한 근거가 없는 초기 버전은 확인 가능한 범위만 기록했습니다.

## 초기 버전

### v1.0.0

- 첫 번째 명시적 제품 버전입니다.
- 이후 2.x 개발의 기준이 된 초기 검색 애플리케이션 상태를 확립했습니다.

### v2.4.0, v2.4.4

- 2.x 버전 계열의 초기 릴리스와 유지보수 버전입니다.
- 당시 커밋은 버전 갱신 중심이며, 현재 구조와 직접 연결되는 세부 기능 계약은 남아 있지 않습니다.

### v2.6.0, v2.7.0, v2.8.0, v2.9.0, v2.9.1

- 초기 GUI·검색 기능을 빠르게 확장한 연속 릴리스입니다.
- 중간에 `src`, `tests`, `scripts` 디렉터리를 삭제·재구성한 커밋이 있어, 버전 간 파일 구조가 연속적이지 않습니다.

### v3.0.0, v3.0.1

- 3.x 제품 계열로 전환했습니다.
- 버전 갱신과 배포 스냅샷이 중심이며, 후속 버전에서 구조가 다시 교체되었습니다.

### v3.5.1, v3.6.0, v3.6.1, v3.7.4

- 3.x 유지보수 및 배포 버전입니다.
- 이 구간에도 이전 산출물을 정리하고 다음 구조를 추가하는 커밋이 포함되어 있어, 세부 동작은 해당 커밋의 스냅샷으로 확인해야 합니다.

- Rust 배치 검색이 실패하더라도 이미 전달한 결과 수와 건너뛴 파일 집계를 보존합니다. 실패 종료를 정상 완료 로그로 표시하지 않고, 한글·영문에서 결과 불완전을 명시합니다.
- 폴더·파일 목록 검색, 결과 없음·부분 결과, 한글·영문을 조합한 회귀 테스트 8개를 추가했습니다. 검색·파일 선별 알고리즘은 변경하지 않았습니다.
- 배포 전 작업본의 A–J 준비 실행 1회와 측정 5회를 기록했습니다. 측정 5회 모두 결과 159건·건너뛴 파일 0건이며 시간 합계 중앙값은 1.174초입니다. 당시 5.9.29 태그는 그대로 유지하며 새 버전에서 측정한 것으로 바꾸지 않습니다.
- `.gitignore`의 중복 숨김 디렉터리 규칙을 정리했습니다. 사용자 표본과 로컬 진단 리포트의 제외 정책은 유지합니다.
- 릴리스 검증에서 Python 전체 테스트 810개 통과·2개 건너뜀, Rust 릴리스 테스트 61개 통과 및 Ruff·Rust 포맷·Clippy 통과를 확인했습니다. 재빌드한 6.0.1 엔진을 사용하는 워커·검색 신뢰도 회귀 테스트 90개도 통과했습니다.
- EXE의 프로젝트 코드·단일 Rust 엔진 포함 검사, Qt ICU 및 격리 실행 초기화 검증을 통과한 뒤 `dist/StringFinder.exe`를 교체했습니다. Python/Rust 버전은 모두 6.0.1이며, 자동 검증은 실제 화면의 수동 사용성 검증을 대신하지 않습니다.
- 시작 구간 소요 시간 로그와 계측 클래스·연결 코드·한영 리소스를 제거하고 최종 6.0.1 EXE를 재빌드해 반영했습니다. 첫 화면 표시 후 백그라운드 로그 정리와 테마 1회 적용은 유지합니다.
- 6.0.1을 마스터(안정) 버전으로 지정했습니다. 최종 EXE는 72,858,658바이트이며 SHA-256은 `db8edfbd72210e06b910e9d56d98436f8f38e96f72bde0af527d43dbe4240bed`입니다. 프로젝트 코드·단일 Rust 엔진 포함 검사와 격리 Qt/테마/엔진 초기화 검증을 통과했습니다. 빌드 환경의 다른 프로젝트 경로는 제외했습니다.
- 6.0.1 성능 기준을 준비 실행 1회·측정 5회의 새 기록으로 정리했습니다. 모든 측정에서 결과 159건·건너뛴 파일 0건, 시간 합계 중앙값 1.249초입니다. 과거 최적화·회귀·보류 기록은 개발자 가이드 9절로 옮기고 원본 히스토리는 보존했습니다. 측정 당시 엔진과 최종 재빌드 엔진의 해시는 성능 기준 문서에서 구분합니다.
- 최종 재배포 후 기본 Python 검증 798개 통과·2개 건너뜀과 추가 stress/chaos 검증 10개 통과를 확인했습니다(합계 808개 통과·2개 건너뜀). 시작 계측 테스트 2개를 제거한 뒤의 수치이며, 앞선 810개 통과 기록과 구분합니다. Rust 릴리스 테스트 61개, Ruff·Rust 포맷·Clippy도 통과했습니다.

### v6.0.1 테스트 정리 및 메타데이터 재배포

- 실패 조건이 없는 문자열 중복값 검사와 제품 배치 구현을 호출하지 않는 자체 시뮬레이션 테스트 2개를 제거했습니다. 문자열 참조·상수명 검사와 실제 워커·검색 무결성 테스트는 유지했습니다.
- Rust 감시 스레드 검증을 별도 프로세스의 실제 검색 20회로 보강했습니다. 반환 결과와 스레드 회수를 검사하며, 검색 오류·프로세스 오류·10초 시간 초과는 테스트 실패로 처리합니다. 무조건 1초 대기는 조건부 종료 대기로 바꿨습니다.
- Qt 창 종료 및 공통 정리 절차는 안전한 테스트 격리를 위해 유지했습니다. 이 변경은 검색 알고리즘이나 사용자 기능의 최적화가 아닙니다.
- Python 패키지에 진입 모듈 `sf_main`을 명시하고 프로젝트 설명·문서 주소를 갱신했습니다. Rust 패키지에 최소 도구 버전 1.88과 작성자·설명·저장소를 명시했습니다. 의존성과 제품 버전은 변경하지 않았습니다.
- 같은 6.0.1 버전으로 재배포했습니다. EXE는 72,858,456바이트이며 SHA-256은 `0d95e1466c685b6adbf38abf8596b3d87ce0b5bc68e8223639e9a80857f8fdd6`입니다. 프로젝트 소스·단일 엔진 포함 검사와 격리 Qt/테마/엔진 초기화 검증을 통과했습니다. 기존 마스터 선언 당시의 배포 기록과 구분합니다.
- 재빌드 엔진으로 stress·chaos를 포함한 Python 전체 테스트 806개 통과·2개 건너뜀을 확인했습니다. Rust 릴리스 테스트 61개와 Ruff·Rust 포맷·Clippy도 통과했습니다. 삭제한 테스트 2개 때문에 이전 전체 통과 수 808개와 차이가 있으며, 실행 시간 차이를 검색 성능 개선으로 해석하지 않습니다.

## 현재 설계로 이어진 결정

- 일반 검색은 Rust 엔진의 속도를 우선하고, 누락 방지 검색은 유니코드와 손상 인코딩 대응을 우선합니다.
- JSON/XML 특수 검색은 검색어가 먼저 발견되어도 문서 끝까지 구문 검증을 완료한 뒤 결과를 확정합니다. Excel은 시트별 실패를 분리하며, 존재만 확인에서는 첫 결과를 찾으면 해당 파일의 검사를 종료하므로 이후 시트까지 검증했다는 의미는 아닙니다.
- 제한·오류·접근 실패는 정상 매치와 분리된 스킵 사유로 전달합니다.
- 사용자 표시 문자열은 한국어와 English 리소스에 함께 등록합니다.
- A–J 측정 원본은 [벤치마크 히스토리](benchmark_history.md), 현재 성능 기준은 [검색 성능 기준](ENGINE_PERFORMANCE_BASELINE.md), 속도 최적화의 적용·보류 판단과 과거 비교 근거는 [개발자 가이드 9절](DEVELOPER_GUIDE.md#9-검색-성능-개선과-회귀-검토-이력)에서 관리합니다. 이 문서는 일반 기능 변경과 신뢰도·배포 검증을 기록합니다.

## 이력 검증 방법

특정 버전의 실제 변경을 재확인하려면 다음 명령을 사용합니다.

```powershell
git show --stat <커밋>
git show <커밋> -- <파일>
git diff <이전 커밋>..<현재 커밋> -- <파일>
```

초기 버전처럼 커밋 메시지가 단순한 경우에는 해당 커밋의 파일 스냅샷과 다음 버전의 차이를 함께 확인해야 하며, 이 문서의 요약을 세부 API 계약으로 사용해서는 안 됩니다.
