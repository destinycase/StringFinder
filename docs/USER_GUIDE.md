# StringFinder 사용자 가이드 (User Guide)

- **버전:** StringFinder v5.8.6
- **최종 수정일:** 2026-09-05
- **공식 지원 OS:** Windows 10/11 (64-bit)

---

## 1. StringFinder 소개

**StringFinder**는 수만 개의 소스 코드와 대용량 파일에서 원하는 문자열을 빠르게 찾아내는 **멀티스레드 파일 검색 도구**입니다. 실제 속도는 저장장치, 파일 수·형식, 검색 옵션에 따라 달라집니다.

### 🌟 주요 특징
- ⚡ **고속 검색**: Rust 기반 엔진(`Aho-Corasick`, `mmap`, 멀티코어 병렬 처리)을 사용합니다. 실제 시간은 파일 크기·개수, 저장장치, 검색 모드와 결과 수에 따라 달라집니다.
- 🌳 **구조화 데이터 정밀 탐색**: JSON(스칼라 값과 경로), XML(태그·속성 경로), Excel(시트 및 셀 좌표) 특수 검색을 지원합니다.
- 🔍 **스마트 문맥 미리보기**: 매칭된 검색어 전후의 코드 라인을 구문 강조(Syntax Highlighting)와 함께 즉시 확인합니다.
- 💻 **외부 에디터 원클릭 연동**: 상세 매치 항목을 더블 클릭하면 VS Code, Cursor 등 설정된 에디터에서 해당 위치를 엽니다.
- 📑 **다중 탭 & 세션 복원**: 여러 검색 작업을 탭으로 띄워두고 프로그램을 다시 시작해도 이전 검색 상태가 그대로 복원됩니다.

## 2. 시작하기

### 2.1 시스템 요구사항
- **운영체제:** Windows 10/11 64-bit (공식 배포본 기준)
- **메모리:** 최소 4GB RAM (8GB 이상 권장)
- **디스크 공간:** 실행 파일과 사용자 데이터 생성을 위한 100MB 이상의 여유 공간

> Linux/macOS에서 소스 실행을 시도할 수 있지만, 현재 공식 배포본과 빌드·회귀 검증은 Windows 기준입니다.

### 2.2 실행 방법
- **배포용 실행 파일 (`StringFinder.exe`):** 다운로드한 실행 파일을 더블 클릭하여 즉시 실행합니다. (별도 설치 불필요)
- **개발 모드 실행 (Python):** Python 3.12 이상과 Rust toolchain이 필요합니다.
  ```bash
  pip install -e ".[dev]"
  python build_rust.py
  python run.py
  ```

## 3. 메인 인터페이스 둘러보기

```
┌────────────────────────────────────────────────────────────────────────┐
│ [상단] 검색 탭 관리                                      [설정]           │
├────────────────────────────────────────────────────────────────────────┤
│ [상단 검색 패널]                                                        │
│  검색어: [                                    ▼]  [ 🔍 검색 ] [ ⏹ 중지 ]│
│  [ ] 정밀 검색  [ ] 존재 여부만 확인  [x] 숨김 파일/폴더 제외               │
├───────────────┬────────────────────────────────────────────────────────┤
│ [도크 필터 패널]│ [검색 결과 테이블] (실시간 스트리밍)                     │
│ 📁 폴더 선택   │ ------------------------------------------------------ │
│ [ C:\Projects ]│ 파일명          │ 매치 수 │ 경로                       │
│               │ ------------------------------------------------------ │
│ 🏷️ 확장자 필터 │ main.rs         │ 3건     │ src/main.rs                │
│ [ py, rs, ts ]│ search.py       │ 12건    │ src/core/search.py         │
│               ├────────────────────────────────────────────────────────┤
│ 📄 파일명 필터 │ [코드 문맥 미리보기] (Syntax Highlighting)              │
│ [ *test*     ]│ 41:     let mut results = Vec::new();                  │
│               │ 42: ▶   let pattern = normalize_unicode(query);       │
│               │ 43:     if pattern.is_empty() { return results; }      │
├───────────────┴────────────────────────────────────────────────────────┤
│ [상태바] 준비 완료 | 소요 시간: 00:00.08 | 스캔: 1,420개 | 매치: 15건   │
└────────────────────────────────────────────────────────────────────────┘
```

1. **상단 검색 패널:** 검색어 입력(과거 이력 지원), 기본 검색 옵션, 특수 모드 선택 및 검색/중지 버튼
2. **도크 필터 패널 (좌측):** 검색 대상 폴더 추가/제거, 검색할 파일 확장자 선택, 파일명 글로브 필터 지정
3. **검색 결과 뷰어 (중앙):** 매칭된 파일 목록 및 세부 매치 위치를 실시간으로 표시
4. **문맥 미리보기 (하단/우측):** 선택한 매칭 라인의 전후 문맥을 에디터 스타일로 미리보기
5. **상태·요약 영역:** 검색 상태, 경과 시간, 스캔·매치·스킵 수를 검색 중과 완료 후 확인

> 검색이 진행되는 동안 검색 조건과 탭 조작은 잠깁니다. 다른 탭에서 동시에 검색을 시작할 수 없으며, 완료 또는 중지 후 다시 조작할 수 있습니다.

## 4. 핵심 기능 및 검색 모드 가이드

### 4.1 기본 텍스트 검색 옵션
- **대소문자 구분 (Case Sensitive):** 현재 UI에는 별도 대소문자 구분 옵션이 없습니다. 일반 검색은 엔진의 대소문자 비구분 동작을 사용합니다.
- **정확히 일치 (Exact Match):** 특수 검색 모드에서 `XML/JSON/Excel (정확히 일치)`를 선택하면 구조화된 텍스트 값 또는 Excel 셀 값이 검색어와 일치하는 경우를 찾습니다. 일반 모드의 줄 전체 일치 옵션은 제공되지 않습니다.
- **바이너리 파일 제외 (Exclude Binary):** 이미지, 실행 파일, 압축 파일 등 바이너리 파일을 검색 대상에서 자동으로 건너뜁니다. (UTF-16 텍스트 파일은 안전하게 보존됨)

---

### 4.2 특수 검색 모드 (Special Search Modes)

| 모드명 | 주요 기능 및 표시 형식 | 적합한 활용 사례 |
| :--- | :--- | :--- |
| **JSON 모드** | JSON 스칼라 값과 경로(`/items/0/name`) 표시 | 대용량 API 응답, 설정 JSON 파일 탐색 |
| **XML 모드** | 부모-자식 태그·속성 경로(`/root/user/@id`) 표시 | XML 설정, Android 매니페스트, UI 레이아웃 파일 |
| **Excel 모드** | 시트 이름·셀 좌표·값(`Sheet1`, `B12`) 표시 | Excel 데이터 시트, 번역 텍스트 테이블 탐색 |

> [!TIP]
> **대용량 JSON 검색 시 메모리 보호:**  
> StringFinder의 Rust JSON 모드는 Visitor 기반 streaming 파싱을 사용합니다. 설정된 JSON 크기 제한을 넘으면 해당 파일만 건너뛰고 다른 파일 검색은 계속합니다. 메모리 보호 기준은 장치의 RAM 크기에 따라 조정됩니다. 시스템에는 전체 RAM의 5%를 남기되 최소 512MB, 최대 2GB 범위로 계산하고, StringFinder 프로세스 트리는 전체 RAM의 60%와 8GB 중 작은 값을 상한으로 사용합니다. 현재 메모리는 안전하지만 개별 JSON/XML 구조 검색의 예상 사용량까지 더하면 이 안전 여유를 침범하는 경우에는 전체 검색을 중단하지 않고 해당 파일만 건너뜁니다. JSON 깊이 제한에 도달하면 제한보다 깊은 하위 영역만 검색하지 않고, 이미 찾은 결과는 유지한 채 해당 파일과 사유를 상단 **건너뛴 파일 수** 패널 및 `파일 목록 보기` 팝업에 표시합니다.

> [!IMPORTANT]
> **XML 문서 검증 및 DTD 제한:**
>
> XML 모드는 검색어를 찾은 뒤에도 문서 끝까지 구문을 검증합니다. 닫는 태그 불일치, 여러 루트 요소, 루트 뒤의 XML 선언·DOCTYPE처럼 손상되거나 순서가 잘못된 문서는 결과에 포함하지 않고 스킵 사유를 표시합니다. `<!DOCTYPE ...>`을 사용하는 DTD와 사용자 정의 엔터티 확장은 지원하지 않으며, 해당 파일은 일반 XML 구문 오류와 구분되는 DTD 미지원 사유로 스킵됩니다. DTD 기반 엔터티 값이 필요하면 신뢰할 수 있는 도구로 엔터티를 일반 텍스트 값으로 치환한 XML을 검색하십시오.

특수 모드를 선택하면 해당 확장자가 자동으로 검색 대상이 됩니다. JSON 모드는 `.json`, XML 모드는 `.xml`, Excel 모드는 `.xlsx`, `.xlsm`, `.xls`, `.xlsb`를 대상으로 하며, 일반 모드에서 설정한 확장자 목록은 특수 모드에 적용되지 않습니다.

`스마트 스캔`은 현재 GUI의 특수 모드 선택지로 제공되지 않습니다. 개발자용 Rust/Python API에서 키워드가 포함된 파일 목록을 얻는 내부 기능입니다.

## 5. 결과 탐색 및 편의 기능

### 5.1 외부 에디터(VS Code 등) 연동
- 결과 파일 목록을 **더블 클릭**하면 시스템 기본 앱으로 파일을 엽니다.
- 상세 매치 항목을 **더블 클릭**하면 설정된 외부 편집기로 해당 줄을 엽니다.
- 내장 선택지: **VS Code, Cursor, Notepad++, Sublime Text**, 시스템 기본 앱, 사용자 지정 실행 파일. IntelliJ는 내장 선택지가 아니지만 사용자 지정 실행 파일로 연동할 수 있습니다.
- 사용자 지정 편집기는 `{file}`과 `{line}` 치환자를 사용할 수 있습니다. 명령은 쉘을 거치지 않고 실행되므로 쉘 명령문을 인자 템플릿에 넣는 방식은 지원하지 않습니다.

### 5.2 결과 복사 및 내보내기
- **`Ctrl + C`**: 결과 파일 목록에서는 선택한 경로를, 상세 매치 목록에서는 선택한 행 내용을 복사합니다.
- **우클릭 메뉴의 결과 내보내기**: `.xlsx` 또는 `.txt` 파일로 검색 결과를 저장합니다. Excel 내보내기에는 파일 목록과 상세 매치 시트가 포함됩니다.

파일명 필터는 파일명에 대해 glob 패턴으로 적용됩니다. 예를 들어 `*test*`를 입력하면 이름에 `test`가 포함된 파일을 찾고, 일반 문자열을 등록하면 내부적으로 포함 검색 패턴으로 처리됩니다. 여러 검색어는 쉼표로 구분할 수 있습니다.

## 7. 환경설정 가이드 (Settings)

메인 창 우측 상단의 `설정` 버튼에서 애플리케이션 동작을 세밀하게 튜닝할 수 있습니다.

- **언어:** `한국어` 또는 `English`를 선택할 수 있습니다. 실행 중 화면에 두 언어가 섞이지 않도록 프로그램을 다시 시작할 때 적용됩니다.
- **외부 편집기 설정:** 선호하는 코드 에디터 실행 파일 경로 및 명령줄 인수 템플릿(`{file}:{line}`)을 등록합니다.
- **검색 한도 설정:** 
  - **파일당 최대 매치 수:** 파일 하나당 수집할 최대 결과 개수 (기본: 5,000건)
  - **전체 최대 매치 수:** 검색 탭 전체의 안전 상한선 (기본: 500,000건)

  파일당 최대 매치 수에 도달하면 해당 파일의 상한 이후 결과만 생략됩니다. 상한까지 수집한 검색 결과는 그대로 표시되며, 누락 가능성을 놓치지 않도록 해당 파일이 상단 **건너뛴 파일 수** 패널과 목록 팝업에도 안내됩니다. 한 파일에서 파일당 매치 제한과 JSON 깊이 제한이 함께 발생해도 파일 수는 한 번만 계산하고, 팝업 사유에 두 안내를 함께 표시합니다.
- **메모리·구조 검색 한도:**
  - **구조 검색 파일 크기 안전 상한:** 기본 500MB. 모든 JSON 검색과 정밀 검색의 Python XML 경로에 적용되며, Rust 기본 XML 검색에는 적용되지 않습니다. 이 값은 실제 메모리 사용량이 아니라 입력 파일 크기 기준입니다.
  - JSON 최대 깊이: 기본 20,000
  - **Excel 존재 확인 최대 검사 셀 수:** 기본 500,000. `존재 여부만 확인` 검색에서 파일별로 적용되며, 한도에 도달하면 검색 결과 없음으로 처리하지 않고 해당 파일을 부분 검색으로 안내합니다.
  - 파일당 최대 매치 수: 기본 5,000건
  - 전체 최대 매치 수: 기본 500,000건
- **정밀 검색 전용 처리 기준:**
  - **일반 텍스트 소형 파일 경로 기준:** 이 크기 미만의 일반 텍스트는 64KB 인코딩 검사 후 줄 단위 소형 파일 경로로 검색합니다.
  - **JSON Mmap 읽기 전환 크기:** 이 크기 이상의 JSON은 Mmap으로 읽지만, JSON 문서 분석은 전체 문서를 대상으로 수행합니다.
  - **정밀 검색 배치 완료 대기 제한:** 기본 600초. 어떤 파일 배치도 제한 시간 안에 완료되지 않으면 특정 파일 하나가 아니라 정밀 검색의 전체 Python 작업 풀을 종료합니다.

  위 세 설정은 정밀 검색의 Python 처리 경로에만 적용되며 Rust 기본 검색의 동작이나 성능에는 영향을 주지 않습니다.
- **테마 전환:** 시스템 설정에 맞추거나 **다크 테마 / 라이트 테마**를 직접 선택할 수 있습니다.

### 7.1 저장 위치와 데이터 삭제

- Windows 설정·세션·로그 위치: `%APPDATA%\StringFinder\`
- `APPDATA`를 사용할 수 없으면 사용자 홈의 `.stringfinder\`를 사용합니다.
- 설정 창의 `데이터 폴더 열기`로 실제 경로를 확인할 수 있습니다.
- `모든 데이터 삭제`는 설정, 저장된 세션과 로그를 삭제하므로 필요한 데이터는 먼저 백업하십시오.

### 7.2 결과 상한과 스킵

파일당 또는 전체 매치 수가 상한에 도달하면 결과가 제한될 수 있으며, 제한으로 생략된 항목은 결과에 별도 truncation 표시가 남을 수 있습니다. 이는 검색 실패와 다릅니다. 스킵 배지와 로그 탭에서 접근 오류, 파일 변경·잠금, 파일 크기 제한, 구조 데이터 보호 한도를 구분해 확인하십시오.

`파일 메모리 예산 부족`은 현재 시스템 전체가 이미 위험하다는 뜻이 아닙니다. JSON/XML 파일 하나를 구조적으로 펼쳐 처리할 때 필요한 메모리를 보수적으로 예상한 결과, 처리 후 안전 여유를 유지하기 어렵다고 판단하여 그 파일만 건너뛴 상태입니다. 다른 파일의 검색 결과는 유지됩니다. 반대로 실제 가용 메모리가 동적 예약량 아래로 내려가거나 StringFinder 프로세스 트리가 상한에 도달하면 시스템 안정성을 위해 검색 전체가 중단됩니다. 작업 관리자에 표시되는 단순 메모리 사용률만으로 중단 여부를 결정하지는 않습니다.

JSON·XML·Excel 구문 오류, 파일 접근·잠금, 크기·메모리 제한 등 건너뛴 파일의 원인은 설정에서 선택한 언어로 표시됩니다. 다른 언어로 저장된 이전 세션을 불러와도 현재 언어로 다시 표시하며, 운영체제·Rust·Calamine의 원본 진단은 문제 분석을 위해 로그 탭에만 남습니다.

## 8. 자주 묻는 질문 (FAQ) & 문제 해결

**Q. 검색 중에 특정 파일들이 스킵(Skip)되었다고 표시됩니다.**  
A. 접근 권한이 없거나, 다른 프로세스에 의해 단독 잠금된 파일, 또는 처리 예상 메모리가 장치별 안전 예산을 초과한 극단적인 대용량 파일은 건너뜁니다. 상태바의 스킵 건수를 클릭하면 상세 사유를 확인할 수 있습니다. `파일 메모리 예산 부족`은 해당 파일만 제외했다는 의미이므로 다른 결과는 계속 확인할 수 있습니다.

**Q. 검색 중에 창이 멈춘 것처럼 보입니다.**  
A. Rust 검색은 백그라운드 worker와 병렬 엔진으로 실행되며, 결과는 배치 단위로 UI에 전달됩니다. 검색 중에는 `중지` 버튼을 사용하십시오. 저장장치가 느리거나 파일 수가 많으면 중지 처리에 시간이 걸릴 수 있습니다.

**Q. 이전에 검색했던 결과와 탭들을 그대로 유지하고 싶습니다.**  
A. 정상적으로 프로그램을 종료하면 탭, 필터 조건, 검색 결과와 로그가 세션에 저장되며 다음 실행 시 복원됩니다. 강제 종료나 프로세스 장애가 발생한 경우 마지막 변경분은 저장되지 않을 수 있습니다.

**Q. JSON에서 키 이름도 검색되나요?**  
A. JSON 특수 검색은 현재 JSON 스칼라 값과 해당 경로를 검색합니다. 객체 키 자체를 검색하는 기능으로 해석해서는 안 됩니다.

**Q. 올바르게 보이는 XML이 DTD 미지원으로 스킵됩니다.**

A. StringFinder는 예측 가능한 메모리 사용과 안전한 파싱을 위해 DTD 선언과 사용자 정의 엔터티 확장을 처리하지 않습니다. DTD를 제거하고 엔터티 참조를 실제 텍스트 값으로 치환한 뒤 다시 검색하십시오. XML 선언은 사용하는 경우 파일 시작 부분에 한 번만 있어야 합니다.

**Q. 결과가 없는데 파일에 문자열이 있습니다.**  
A. 파일 확장자·파일명 필터, 바이너리 제외, 인코딩, 특수 모드와 정확히 일치 옵션을 확인하십시오. 일반 검색에서 복잡한 Unicode equivalence가 필요하면 `정밀 검색`을 사용해 보십시오.

**Q. 일부 파일이 스킵되었습니다.**  
A. 결과 화면의 스킵 배지 또는 `파일 목록 보기` 버튼을 클릭하면 현재 언어로 표시된 사유를 확인하고 전체 목록을 복사할 수 있습니다. 접근 권한, 파일 잠금·변경, 1GB 초과 파일, JSON 크기 또는 Excel 셀 검사 한도 초과 등이 원인일 수 있습니다. 파일당 매치 제한, JSON 깊이 제한, Excel 존재 확인 셀 제한은 파일 전체 실패와 구분되는 **일부 결과·영역 미검사 안내**입니다. 한도 전에 수집한 정상 결과는 검색 결과에 유지됩니다. 엔진의 원본 진단은 로그 탭에서 확인할 수 있습니다.

**Q. 일반 모드에서 파일이 검색되지 않습니다.**  
A. 폴더가 추가되어 있고 해당 확장자가 선택되어 있는지 확인하십시오. 바이너리 제외가 켜져 있으면 NUL 바이트가 포함된 파일은 제외될 수 있습니다. UTF-16 텍스트는 인코딩 감지 결과에 따라 일반 텍스트로 처리됩니다.

**Q. 검색 결과가 너무 많습니다.**  
A. 파일당 최대 매치 수에 도달한 파일은 상단 **건너뛴 파일 수** 패널과 목록 팝업에서 확인할 수 있습니다. 설정의 파일당·전체 최대 매치 수를 조정하거나 파일명·확장자 필터를 좁히십시오. 상한을 크게 올리면 결과 저장과 UI 갱신에 더 많은 메모리와 시간이 필요합니다.
