# 9차 안정 버전 — v8.1.1

선언일: **2026-11-27** · 이전 기준판: [v7.7.1](archive/before-v8/master-baseline-v7.7.1.md)

v8.1.1을 StringFinder의 아홉 번째 안정 버전으로 지정합니다. 코드는 7.7.8과 같고 앱 버전 표기만 8.1.1로 올렸습니다. 8 버전부터 검색 엔진의 버전을 앱 버전과 따로 매겨(엔진 1.0.0) 주 버전을 8로 올렸고, 기록도 8.1.1부터 새로 시작합니다. 이 문서는 선언 뒤에는 오탈자·깨진 링크만 고칩니다.

## 기준 소스와 배포물

- 기준 태그: `v8.1.1` (이 문서를 추가한 선언 커밋).
- 제품 기준 커밋(7.7.8 코드와 그 뒤 도구 정리): `d8e99a280ee334de8021bd27a4f30ab7e64c20cd`. 선언 커밋은 여기에 앱 버전 표기·문서·벤치마크 기준선만 더합니다.
- 앱 버전 **8.1.1**, 엔진 버전 **1.0.0**. 창 제목에 `StringFinder v8.1.1 (Engine v1.0.0)`으로 보입니다.
- 배포 파일: `StringFinder-v8.1.1.exe` (Windows 단일 실행 파일). `dist/StringFinder.exe`는 이 파일의 사본입니다.

| 파일 | 크기(bytes) | SHA-256 |
| --- | ---: | --- |
| `StringFinder-v8.1.1.exe` | 72160855 | `aaa8809e534885875a982192d742dcb36b6e97e57290d4cdc9bcba59e9a897a1` |

포함된 Rust 엔진(`sf_engine.pyd`, 엔진 1.0.0)의 SHA-256은 `d461f3316764bf3ee20347f8ab2b5291a144763bc6caa16a7c98e3f5c77c91ac`이고, 엔진 소스 지문(`SOURCE_HASH`)은 `04288e99f5a9bca1`입니다. 엔진은 7.7.6에서 만든 것과 같은 파일입니다.

## v7.7.1 이후 바뀐 기능

검색 엔진의 검색 동작은 7.7.1과 같습니다.

- **엔진 버전 분리(7.7.6~7.7.8)**
  - 검색 엔진의 버전을 앱 버전과 따로 매깁니다(엔진 1.0.0). 엔진 코드가 바뀌지 않은 앱 버전은 엔진을 다시 빌드하지 않아, 실행 파일 안의 엔진이 같은 파일로 유지됩니다.
  - 창 제목에 앱 버전과 엔진 버전이 함께 보이며, 화면 언어와 상관없이 영어입니다.
- **복사(7.7.4·7.7.5)**
  - 파일 목록의 오른쪽 메뉴에 **파일만 복사**(파일 이름만)와 **폴더만 복사(중복 제외)**가 있습니다.
  - **경로 복사**와 검색 상세의 **내용 복사**(둘 다 Ctrl+C)가 목록에 보이는 순서로 복사해, 다른 복사 항목과 순서가 같습니다.
- **검색어 안내(7.7.3)**: 검색어 입력칸이 비어 있으면 "검색할 문자열을 입력하세요. (대소문자는 구분하지 않으며, 최대 1,000자를 입력할 수 있습니다.)"가 보입니다.
- **필터 여백(7.7.2)**: 확장자·파일명 사이 구분선이 얇아지고, 파일명 제목이 구분선에서 떨어져 보입니다.
- **검색 결과:** 33개 벤치마크 표본의 결과 지문·일치 수가 7.7.1과 같습니다. 속도는 [성능 기록](PERFORMANCE_HISTORY.md)에 있습니다.

## 업데이트할 때

- 세션 저장 형식은 7.7.1과 같습니다(형식 3). 7.7.1에서 저장한 탭은 결과와 함께 그대로 열리고, 8.1.1에서 저장한 탭도 7.7.1에서 열립니다.
- 7.2.1 이전 버전에서 저장한 탭은 7.7.1과 마찬가지로 검색 조건만 불러오고 결과는 한 번 비워집니다.

## 알려진 제약

- UTF-16·CP949 archive는 검색하는 동안 파일 전체의 UTF-8 사본을 만들어, 수 GB 파일은 메모리가 부족하면 건너뜁니다.
- JSON 키 안의 `.`은 중첩 경로와 같은 글자로 보입니다.
- 머리글 정렬 기준과 검색 상세에서 직접 끈 열 비율은 저장되지 않습니다(프로그램을 다시 켜면 기본값).
- 결과가 아주 많을 때 백그라운드 저장 중(1~2초) 화면 반응이 조금 느려질 수 있습니다.
- 수천 개 파일(수십만 건)을 한꺼번에 고른 상태에서 상세 목록을 거르면 입력이 멈춘 뒤 1~2초 걸립니다.

성능 기준값은 [벤치마크 기준선](BENCHMARK_BASELINE.md), 버전별 변경은 [개발 히스토리](DEVELOPMENT_HISTORY.md)에 있습니다.
