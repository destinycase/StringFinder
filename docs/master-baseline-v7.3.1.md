# 4차 안정 버전 — v7.3.1

선언일: **2026-11-15** · 이전 기준판: [v7.2.1](master-baseline-v7.2.1.md)

v7.3.1을 StringFinder의 네 번째 안정 버전으로 지정합니다. 코드는 7.2.9와 같고 버전 표기만 7.3.1로 올려 다시 빌드했습니다. 7.2.1 이후 세션 저장 형식과 엔진 결과 구분 방식이 바뀌어 두 번째 숫자를 올렸습니다(사용자 지정). 이 문서는 선언 뒤에는 오탈자·깨진 링크만 고칩니다.

## 기준 소스와 배포물

- 기준 태그: `v7.3.1`. 이 태그는 이 고정 문서를 추가한 선언 커밋을 가리킵니다.
- 제품 기준 커밋(7.2.9 코드): `6d943cb5d79b62ad5ced39ab4bcab0868efe967e`. 선언 커밋은 여기에 버전 표기·문서만 더합니다.
- 배포 파일: `StringFinder-v7.3.1.exe` (Windows 단일 실행 파일). `dist/StringFinder.exe`는 이 파일의 사본입니다.

## v7.2.1 이후 바뀐 기능

- **표식처럼 생긴 줄:** `ERR_LOGIN_FAILED|…`처럼 `ERR_…|`로 시작하는 줄이 검색어와 일치하면 그 파일의 결과가 모두 빠지고 "알 수 없는 오류로 건너뜀"으로 나오던 문제를 고쳤습니다. 이제 엔진이 결과를 만드는 곳에서 일치와 안내를 구분하므로, 줄 내용이 어떻게 생겼든 일치는 결과에 나옵니다. `__SF_`로 시작하는 줄도 같습니다.
- **전체 결과 수 상한:** 긴 줄(4,096바이트 초과)의 일치도 함께 셉니다. 화면의 일치 수와 같은 기준입니다.
- **건너뛴 사유의 언어:** 사유를 언어와 상관없는 코드로 저장해, 화면 언어를 바꾸면 저장된 사유도 그 언어로 보입니다. 줄바꿈이 든 Excel 시트 이름의 사유도 탭을 다시 열 때 남습니다(줄바꿈은 공백으로 바뀝니다).
- **검색 모드 저장:** 검색 모드를 언어와 상관없는 값으로 저장해, 화면 언어를 바꿔도 같은 모드로 열립니다. 세션 파일을 손으로 고쳐 `json`·`EXCEL`처럼 적어도 읽습니다.
- **검색 엔진 속도:** 같은 표본의 검색 결과가 7.2.1과 같고, 새로 잰 기준선은 7.2.1 기준선의 0.95~1.12배입니다([성능 기록](PERFORMANCE_HISTORY.md)).
- 그 밖에 7.2.2~7.2.8은 쓰지 않는 코드와 예전 형식 읽기 코드를 정리했습니다. 화면과 검색 동작은 바뀌지 않습니다.

## 업데이트할 때 한 번 겪는 변화

- **저장된 탭의 결과가 한 번 비워집니다.** 7.2.1(또는 그 이전) 버전으로 저장한 탭을 열면 검색어·검색 모드·폴더·그룹·확장자·파일명 조건만 남고, 결과는 비며 "예전 형식으로 저장된 탭이라 검색 조건만 불러왔습니다. 다시 검색해 주세요."가 나옵니다. 다시 검색한 뒤로는 결과가 그대로 복원됩니다.
- 5.9.17 이전 세션에 쉼표로 적힌 파일명 조건은 읽지 않습니다. 그 뒤 버전의 체크 목록은 그대로 복원됩니다.
- 7.3.1로 저장한 세션을 7.2.1 등 이전 버전으로 여는 경우는 확인하지 않았습니다. 이전 버전으로 되돌아가려면 설정 내보내기로 미리 백업해 두기를 권합니다.

## 알려진 제약

- JSON 키 안의 `.`은 중첩 경로와 같은 글자로 보입니다.
- 머리글 정렬 기준은 세션에 저장되지 않습니다.
- 결과가 아주 많을 때 백그라운드 저장 중(1~2초) 화면 반응이 조금 느려질 수 있습니다.
- 수천 개 파일(수십만 건)을 한꺼번에 고른 상태에서 상세 목록을 거르면 입력이 멈춘 뒤 1~2초 걸립니다.
- 검색이 진행 중일 때 결과가 들어와 파일 목록이 다시 만들어지면, 여러 개 고른 선택이 보던 파일 하나로 풀립니다.
