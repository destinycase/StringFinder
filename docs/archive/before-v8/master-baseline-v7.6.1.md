# 7차 안정 버전 — v7.6.1

선언일: **2026-11-22** · 이전 기준판: [v7.5.1](master-baseline-v7.5.1.md)

v7.6.1을 StringFinder의 일곱 번째 안정 버전으로 지정합니다. 7.5.8 코드에 선언 전 검수에서 나온 화면 동작 수정 두 가지(페이지를 넘겨도 상세 유지, 여러 개 중 하나를 풀면 남은 파일 상세)를 더했습니다. 두 번째 숫자는 사용자가 정했습니다. 이 문서는 선언 뒤에는 오탈자·깨진 링크만 고칩니다.

## v7.5.1 이후 바뀐 기능

검색 엔진(Rust) 코드는 7.5.1과 같고, 모두 화면 동작 변경입니다.

- **검색 상세 열 폭(7.5.4·7.5.6·7.5.7)**
  - JSON·XML·Excel·UE archive 검색 상세의 열 폭을 표 폭에 맞춰 나눠 가로 스크롤이 생기지 않습니다. 짧은 열(줄·이름·키)은 좁게, 값 열(UE archive는 원문·번역)이 남는 폭을 똑같이 나눕니다.
  - 미리보기 창과의 경계, 창 크기, 탭 전환에 따라 다시 나눕니다.
  - 셀보다 긴 내용은 "…"로 줄이고 마우스를 올리면 전체 내용을 보여 줍니다. 파일 목록의 긴 이름도 "…"로 줄어듭니다.
  - 머리글에서 열 경계를 끌면 그 비율을 프로그램이 켜 있는 동안 기억합니다.
- **프로그램 전체 로그 창(7.5.3·7.5.6·7.5.7)**
  - 로그 창은 어느 탭에서 열어도 프로그램을 켠 뒤의 모든 로그를 최근 5,000줄까지 같은 내용으로 보여 주고, 검색을 시작해도 비우지 않습니다.
  - **로그 지우기**는 모든 탭을 함께 비웁니다.
  - 탭에 로그를 저장하지 않으며, 이전 실행의 로그는 다시 불러오지 않습니다.
- **선택 유지(7.5.2·7.5.5·7.5.7·7.5.8)**
  - 검색 중 결과가 들어와 목록이 다시 만들어지거나 검색이 끝나도, 고른 파일(여러 개 포함)이 첫 파일로 바뀌지 않습니다.
  - Ctrl+클릭으로 푼 선택은 다시 골라지지 않습니다.
  - 파일 필터로 고른 파일 일부가 숨으면 상세가 남은 파일만, 모두 숨으면 상세가 비워집니다. 파일 목록의 페이지를 넘기는 것은 숨기는 것이 아니라 상세가 그대로 남습니다(7.6.1).
  - 여러 개 중 Ctrl+클릭으로 풀어 하나만 남으면 상세가 남은 파일을 보여 줍니다(7.6.1).
- **검색 결과:** 33개 벤치마크 표본의 결과 지문·일치 수가 7.5.1과 같습니다. 속도는 [성능 기록](PERFORMANCE_HISTORY.md)에 있습니다.

## 업데이트할 때

- 세션 저장 형식은 7.5.1과 같습니다(형식 3). 7.5.1에서 저장한 탭은 결과와 함께 그대로 열립니다. 이전 실행의 로그는 보이지 않습니다.
- 7.6.1에서 저장한 탭도 7.5.1에서 열립니다. 로그는 빈 채로 열립니다.
- 7.2.1 이전 버전에서 저장한 탭은 7.5.1과 마찬가지로 검색 조건만 불러오고 결과는 한 번 비워집니다.

## 알려진 제약

- UTF-16·CP949 archive는 검색하는 동안 파일 전체의 UTF-8 사본을 만들어, 수 GB 파일은 메모리가 부족하면 건너뜁니다.
- JSON 키 안의 `.`은 중첩 경로와 같은 글자로 보입니다.
- 머리글 정렬 기준과 검색 상세에서 직접 끈 열 비율은 저장되지 않습니다(프로그램을 다시 켜면 기본값).
- 결과가 아주 많을 때 백그라운드 저장 중(1~2초) 화면 반응이 조금 느려질 수 있습니다.
- 수천 개 파일(수십만 건)을 한꺼번에 고른 상태에서 상세 목록을 거르면 입력이 멈춘 뒤 1~2초 걸립니다.

성능 기준값은 [벤치마크 기준선](../../BENCHMARK_BASELINE.md), 버전별 변경은 [개발 히스토리](DEVELOPMENT_HISTORY.md)에 있습니다.
