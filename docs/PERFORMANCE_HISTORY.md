# StringFinder 성능 기록

8.1.1부터 [벤치마크 기준선](BENCHMARK_BASELINE.md)과 비교한 측정 결과를 기록합니다. 7.x의 기록은 [v8 이전 성능 기록](archive/before-v8/PERFORMANCE_HISTORY.md), 6.x는 [v7 이전 성능 기록](archive/before-v7/PERFORMANCE_HISTORY.md)에 있습니다.

기록 방법: 측정한 앱·엔진 버전과 날짜, 기준선 대비 비율의 범위, "결과 다름"·"느려짐" 표본과 원인, 측정 범위 밖의 한계를 적습니다. 원본 JSON은 내부 보고서에 둡니다.

## 1. v8.1.1 · 9차 안정 버전 기준선 (2026-11-27)

- 앱 8.1.1 / 엔진 1.0.0. 7.7.8 코드(7.7.2~7.7.8은 화면·버전 표기만 바꿈, 검색 엔진은 7.6.1과 같음)를 8.1.1로 지정하며 33개 표본을 16회차씩 다섯 번 쟀습니다(00:08~00:17).
- 1회차는 시작 직후라 전 표본이 약 1.75배로 느려 버렸습니다. 2~5회차는 7.7.1 기준선의 0.88~1.16배(기하평균 0.99~1.01)로 "느려짐"이 4회차 Q(1.16배) 하나였고, 다른 회차에서는 Q도 기준 안이라 흔들림으로 봅니다.
- 2회차를 새 기준선으로 저장했습니다. 8.1.1 기준선 ÷ 7.7.1 기준선: 0.93~1.12배. 엔진 코드가 같아 차이가 없습니다.
- 다섯 번 모두 33개 표본의 결과 지문·일치 수가 7.7.1 기준선과 같았습니다.

## 2. v8.1.5·v8.1.6 · 엔진 1.0.1·1.0.2 (2026-11-28)

- 엔진 `lib.rs`를 역할별 파일로 나눈 1.0.1(8.1.5)과 폴더 검색 함수를 단계별로 쪼갠 1.0.2(8.1.6)를 쟀습니다.
- 두 버전 모두 33개 표본의 결과 지문·일치 수가 8.1.1 기준선과 같았습니다.
- 기준선 대비 속도는 그때 장비가 바빠(기준선 엔진 자체도 1.5~2.1배로 나옴) 판정에 쓰지 않았습니다. 대신 엔진 파일을 같은 자리에 번갈아 넣어 견줬습니다.
  - 1.0.1 ÷ 1.0.0: 0.96~1.06배.
  - 1.0.2 ÷ 1.0.1: A 0.998, C 1.002, Q 0.993배(8개 표본 0.975~1.015배).
- 장비가 쉬는 상태의 기준선 대비 측정은 아래 8.2.1 선언 때 했습니다.

## 3. v8.2.1 · 10차 안정 버전 기준선 (2026-11-28)

- 앱 8.2.1 / 엔진 1.0.2. 33개 표본을 16회차씩 다섯 번 쟀습니다.
- 처음 세 번은 장비가 바빠 전 표본이 8.1.1 기준선의 1.2~2.3배로 고르게 느려 버렸습니다(결과는 모두 같음).
- 다른 프로그램을 끈 뒤 잰 네 번째·다섯 번째는 8.1.1 기준선의 0.84~1.03배(기하평균 0.97)로 "느려짐"이 없었고, 두 번끼리 0.92~1.05배로 일치했습니다. 네 번째를 새 기준선으로 저장했습니다.
- 주요 표본(8.2.1 ÷ 8.1.1): A 0.84, C 0.92, Q 0.87, D 1.02, I 1.03, S-ascii 0.98. 파일이 많은 표본(A·Q)이 빠르게 나온 것은 장비 상태의 흔들림일 수 있어 엔진 변경의 효과로 단정하지 않습니다(같은 날 다른 측정에서 A가 1.10배인 적도 있음).
- 다섯 번 모두 33개 표본의 결과 지문·일치 수가 8.1.1 기준선과 같았습니다.
