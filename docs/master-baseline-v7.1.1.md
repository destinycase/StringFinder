# 2차 안정 버전 — v7.1.1

선언일: **2026-11-13** · 이전 기준판: [v6.4.1](archive/before-v7/master-baseline-v6.4.1.md)

## v6.4.1 이후 바뀐 기능

- **검색 엔진 하나로 통합:** 모든 검색을 Rust 엔진 하나로 합니다. 6.4.1의 "변형 글자 검색"(Python, 느림)과 검색 방식 선택이 없어졌고, 기본 검색이 그 비교를 모두 합니다. 대소문자 전체 규칙(`Straße` = `strasse`), 분해형 한글(NFD), CP949·UTF-16 파일, JSON·XML·Excel·UE archive 값이 같은 기준으로 비교됩니다.
- **속도:** 6.4.1 엔진과 번갈아 잰 33개 항목이 모두 0.38~1.03배입니다. 한글 검색어는 최대 약 2.6배, CP949 파일은 약 2배, UTF-16 파일은 약 1.3~1.7배, 구조화 파일 값 검색은 항목에 따라 약 1.1~2.3배 빠릅니다. 바이너리가 많은 폴더의 한글 검색, 일치가 아주 많은 검색의 결과 정리도 빨라졌습니다.
- **검색 모드 선택:** 검색줄 왼쪽의 **검색 모드** 콤보 박스에서 기본 또는 JSON·XML·Excel·UE archive 값만 검색(부분 일치·정확히 일치)을 고릅니다.
- **필터 표시:** 확장자·파일명 필터를 탭 또는 위아래 패널로 함께 볼 수 있습니다(기본 탭).
- **정확성:** 일부를 해석하지 못한 파일을 안내로 알립니다. 정확히 일치 검색은 검색어 앞뒤 공백을 무시합니다. JSON 키의 `/`를 중첩 경로와 구분해 보여 줍니다. 상세 목록 강조가 검색과 같은 기준을 씁니다.
- **화면·안정성:** 검색 종료 후 저장을 백그라운드에서 해 화면이 멈추지 않습니다. 결과 정렬 순서가 실행마다 바뀌지 않고, 머리글 정렬은 전체 결과에 적용됩니다. 전체 결과 상한에 닿으면 엔진이 바로 멈추고 "검색 중지"로 표시합니다. 탭 이름 중복, 데이터 삭제 후 재저장, Excel 내보내기 실패, 깨진 설정 파일 덮어쓰기 같은 문제를 고쳤습니다.
- **호환:** 6.4.1의 설정·세션 파일을 그대로 엽니다. 예전 검색 방식 선택값은 무시됩니다.

## 알려진 제약

- JSON 키 안의 `.`은 중첩 경로와 같은 글자로 보입니다.
- 머리글 정렬 기준은 세션에 저장되지 않습니다.
- 결과가 아주 많을 때 백그라운드 저장 중(1~2초) 화면 반응이 조금 느려질 수 있습니다.

성능 기준값은 [벤치마크 기준선](BENCHMARK_BASELINE.md), 버전별 변경은 [개발 히스토리](DEVELOPMENT_HISTORY.md)에 있습니다.
