# 6차 안정 버전 — v7.5.1

선언일: **2026-11-21** · 이전 기준판: [v7.4.1](master-baseline-v7.4.1.md)

v7.5.1을 StringFinder의 여섯 번째 안정 버전으로 지정합니다. 코드는 7.4.9와 같고 버전 표기만 7.5.1로 올려 다시 빌드했습니다. 두 번째 숫자는 사용자가 정했습니다. 이 문서는 선언 뒤에는 오탈자·깨진 링크만 고칩니다.

## v7.4.1 이후 바뀐 기능

- **정확히 일치 검색 속도(7.4.3):** JSON·XML 값 검색에서 "정확히 일치"를 켰을 때, 한글처럼 변환이 필요 없는 값은 바로 비교합니다.
- **UE 현지화 archive 검색(7.4.4·7.4.5):** 문서 전체를 메모리에 쌓지 않고 읽으면서 판정해 메모리를 크게 덜 쓰고 빨라졌습니다. archive는 고급 설정의 "검색 파일 크기 제한"(최대 1GB)과 상관없이 8GB까지 검색합니다. UTF-16 archive는 파일 크기의 1.5배 안팎, CP949 archive는 3배 안팎 메모리가 필요하며, 부족하면 메모리 부족으로 건너뜁니다(7.4.7).
- **XML 검색과 일치가 많은 검색 속도(7.4.6):** 태그·속성 이름 복사를 줄이고, 같은 줄의 여러 일치에서 줄 내용을 다시 만들지 않습니다.
- **사용 중인 큰 파일(7.4.7·7.4.8):** 다른 프로그램이 저장 중이라 열 수 없는 1GB 넘는 파일은 통째로 메모리에 읽지 않고 "다른 프로그램에서 사용 중"으로 건너뜁니다. 검색 준비 단계에서도 잠금 없이 파일을 읽지 않습니다.
- **수동 UTF-8 선택(7.4.8):** 인코딩을 UTF-8로 고른 채 UTF-8이 아닌 큰 파일을 검색할 때 파일 크기만큼 메모리를 잠깐 쓰던 것을 없앴습니다.
- **폴더 그룹 개수 위치(7.4.9):** 검색 폴더 목록 그룹의 `(선택/전체)` 개수가 그룹 이름 바로 오른쪽에 보입니다.
- **시트 오류 안내 방어(7.4.2):** 시트 오류 안내에 `|`가 없을 때 시트 이름이 비지 않습니다.
- **검색 결과:** 33개 벤치마크 표본의 결과 지문·일치 수가 7.4.1과 같습니다. 속도는 [성능 기록](PERFORMANCE_HISTORY.md)에 있습니다.

## 업데이트할 때

- 세션 저장 형식은 7.4.1과 같습니다(형식 3). 7.4.1에서 저장한 탭은 결과와 함께 그대로 열리고, 7.5.1에서 저장한 탭도 7.4.1에서 열립니다.
- 7.2.1 이전 버전에서 저장한 탭은 7.4.1과 마찬가지로 검색 조건만 불러오고 결과는 한 번 비워집니다.

## 알려진 제약

- UTF-16·CP949 archive는 검색하는 동안 파일 전체의 UTF-8 사본을 만들어, 수 GB 파일은 메모리가 부족하면 건너뜁니다.
- JSON 키 안의 `.`은 중첩 경로와 같은 글자로 보입니다.
- 머리글 정렬 기준은 세션에 저장되지 않습니다.
- 결과가 아주 많을 때 백그라운드 저장 중(1~2초) 화면 반응이 조금 느려질 수 있습니다.
- 수천 개 파일(수십만 건)을 한꺼번에 고른 상태에서 상세 목록을 거르면 입력이 멈춘 뒤 1~2초 걸립니다.
- 검색이 진행 중일 때 결과가 들어와 파일 목록이 다시 만들어지면, 여러 개 고른 선택이 보던 파일 하나로 풀립니다.
