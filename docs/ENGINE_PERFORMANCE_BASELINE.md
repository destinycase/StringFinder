# StringFinder 엔진 성능 기준선

> 측정 기준 버전: **StringFinder 5.9.21** (5.9.22은 성능 진단 도구 개선 릴리스이며 검색 엔진은 변경하지 않음)
> 이 문서는 현재 제품의 공식 성능 기준과 릴리스 판정 규칙을 정의합니다. 과거 실험 및 미채택 최적화 후보는 [개발자 가이드](DEVELOPER_GUIDE.md)의 성능 검토 이력에 기록합니다.

## 공식 기준선

공식 A–J 벤치마크는 `python scripts/benchmark_performance.py`로 실행합니다. 측정 결과는 [벤치마크 히스토리](benchmark_history.md)에 행 단위로 누적합니다.

| 항목 | v5.9.21 측정값 |
|---|---:|
| 벤치마크 세트 | A–J, 10개 |
| 전체 매치 수 | 160 |
| 건너뛴 파일 | 0 |
| 최대 세트 소요 시간 | 0.849초 (Set A) |
| 최대 첫 결과 지연 | 0.169초 (Set E) |
| 최대 RSS | 155.4MB (Set E) |
| 측정 기록 | 2026-09-25, 단일 공식 실행 (`v5.9.21`) |
| 판정 | 통과 |

벤치마크는 일반 텍스트, 대형 파일, 바이너리 혼합, 존재 여부 확인, JSON, XML, 무개행 파일, Excel을 포함합니다. 각 세트의 결과 수와 스킵 수는 회귀 검증을 위해 함께 확인합니다.

이번 실행은 공식 임계값을 모두 통과했고 기대 매치 160건, 스킵 0건을 확인했습니다. Set A는 10,000개 소형 파일을 순회하는 세트이며, 이번 단일 실행의 Set A 시간은 직전 공식 기록보다 길게 측정됐습니다. 단일 실행만으로 성능 회귀를 판정하지 않으며, 반복 측정에서 같은 조건의 중앙값이 지속적으로 악화되는지 확인해야 합니다.

## 릴리스 판정 규칙

새 버전은 다음 조건을 모두 만족해야 합니다.

- 모든 공식 세트의 기대 매치 수 이상을 반환한다.
- 건너뛴 파일이 없어야 한다. 의도된 스킵을 검증하는 별도 테스트는 예외로 기록한다.
- 세트별 시간·지연·RSS가 프로젝트에 정의한 임계값 이내여야 한다.
- JSON/XML 손상 입력, Excel 오류 입력, 존재 여부 확인 경로의 결과 무결성이 유지되어야 한다.
- 반복 측정에서 결과 파일 집합, 매치 수, 스킵 사유가 일치해야 한다.

단일 실행의 수 ms 차이만으로 성능 회귀를 확정하지 않습니다. 회귀 의심 시 동일 장비에서 warm-up을 제외한 반복 측정의 중앙값과 P95를 비교합니다.

## 측정 환경과 해석

측정값은 Windows, Python, PySide6, Rust 확장 모듈 및 현재 장비 상태의 영향을 받습니다. OS 캐시, 백그라운드 작업, 엔진 초기화 상태에 따라 변동할 수 있습니다. RSS는 측정 구간의 관측값이며 장비 전체의 OOM 한계를 의미하지 않습니다.

서로 다른 장비나 데이터셋에서 얻은 값은 직접 비교하지 않습니다. 버전 간 공식 비교는 동일 데이터셋·동일 실행 조건·동일 판정 규칙을 사용한 경우에만 유효합니다.

## 실행 명령

```powershell
python scripts/benchmark_performance.py
```

구조화 파일의 세부 스트레스 및 리소스 보호 검증은 일반 릴리스 기준선과 분리하여 개발자 가이드의 검증 절차에 따라 실행합니다.
