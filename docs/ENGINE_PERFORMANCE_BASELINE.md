# StringFinder 6.1.1 검색 성능 기준

**기준 버전: 6.1.1 (안정 버전)**

이 문서는 현재 성능 비교에 사용할 측정값, 실행 조건과 판정 규칙만 관리합니다. 과거 최적화·회귀·미채택 후보와 이전 기준선은 [성능 개선 기록](PERFORMANCE_HISTORY.md)과 [설계 검토 기록](DESIGN_REVIEW_HISTORY.md), 실행별 원본은 [벤치마크 히스토리](benchmark_history.md), 일반 변경은 [개발 이력](DEVELOPMENT_HISTORY.md)에서 확인합니다.

## 1. 기준선 요약

- **측정 대상:** 6.1.1 Python 소스와 프로젝트 Rust 엔진. 배포 EXE의 시작·압축 해제 시간을 측정한 기록이 아닙니다.
- **측정 방법:** 준비 실행 1회 후 별도 프로세스에서 A–J를 5회 반복. 준비 실행은 통계에서 제외했습니다.
- **결과:** 측정 5회 모두 검색 결과 159건·건너뛴 파일 0건이며 공식 임계값을 통과했습니다.
- **검색 시간 합계 중앙값:** **1.235초**. 실행별 합계는 1.324, 1.235, 1.258, 1.227, 1.230초입니다. 각 실행의 합계를 먼저 구한 뒤 중앙값을 계산했으며 세트별 중앙값의 합과 다릅니다.
- **대표 값:** Set A 중앙값 0.735초, 가장 긴 세트별 첫 결과 지연 중앙값 0.079초(Set E), 측정 5회 중 최대 관측 RSS 150.9MiB(Set E).
- **Excel 공식 세트:** XLSX 밀집 문자열·넓은 빈 영역·수식 결과·날짜/시간의 64개 조합을 조합별 준비 실행 후 5회 측정했습니다. 측정 320건의 결과 계약 검증을 모두 통과했습니다.
- **판정 범위:** A–J의 성능 임계값과 Excel 세트의 결과 계약·동일 조건 성능 비교를 함께 사용합니다. 모든 파일 형식·인코딩·검색어의 정확성이나 모든 검색 경로의 속도를 보장하지 않습니다. 안정 버전 지정도 무결점 보증은 아닙니다.

## 4. 공식 판정 기준

### 4.1 A–J 성능 임계값

수치의 원본은 `scripts/benchmark_performance.py::check_thresholds()`입니다. 문서만 수정해 코드의 기준을 바꾸지 않습니다. 아래 임계값은 여유를 둔 통과 기준이며, 이 값을 넘지 않았다는 이유만으로 이전 버전 대비 회귀가 없다고 결론내리지 않습니다.

| 세트 | 최대 검색 시간(s) | 최대 첫 결과 지연(s) | 최대 RSS(MiB) |
| --- | ---: | ---: | ---: |
| A | 3.0 | 1.5 | 200 |
| B | 1.5 | 0.8 | 200 |
| C | 1.0 | 0.8 | 150 |
| D | 1.5 | 1.5 | 150 |
| E | 1.0 | 0.8 | 200 |
| F | 5.0 | 2.0 | 600 |
| G | 3.0 | 2.0 | 300 |
| H | 1.5 | 1.5 | 200 |
| I | 5.0 | 2.0 | 500 |
| J | 3.0 | 2.0 | 300 |

코드는 기대 결과 수 이상과 건너뛴 파일 0건도 확인합니다. 새 기준선과의 비교에서는 결과가 불필요하게 늘어난 경우도 검사하며, 속도를 평가하기 전에 파일 집합·내용·위치·건너뛴 사유를 별도 회귀 테스트로 확인합니다.

진행 보고 간격의 표준편차(Jitter)는 A–E 0.2초, F–H/J 0.3초, I 0.5초를 넘으면 경고합니다. 현재 코드에서는 실패 조건이 아닙니다. 보고 간격 표본이 부족해 0으로 표시될 수 있으므로 0이 UI의 무지연을 증명하지 않습니다.

### 4.2 Excel 세트 판정

공식 Excel 판정은 `tools/benchmark_excel_suite.py::validate_result()`와 `measure()`를 사용합니다. 4종 표본 × 일반/누락 방지 × 전체 결과/존재 확인 × 첫 위치/끝 위치/2건 적중/무결과의 **64개 조합**을 모두 확인합니다.

| 판정 항목 | 기준 |
| --- | --- |
| 준비·반복 | 조합별 준비 실행 1회 제외 후 측정 5회 |
| 첫·끝 위치 검색 | 각각 결과 1건 |
| 2건 적중 검색 | 전체 결과 2건, 존재 확인 1건 |
| 무결과 검색 | 결과 없음 |
| 내용·위치 | 전체 결과의 값·시트·셀 좌표가 기대값과 일치, 중복 없음 |
| 오류·부분 결과 | 건너뜀·부분 검색·제한 안내를 정상 통과로 인정하지 않음 |
| 기록 조건 | 모든 검색 검증 통과 후에만 실행별 이력 기록 |
| 성능 비교 | 같은 장비·크기·설정·경로에서 3절의 조합별 중앙값·범위와 비교 |

위 결과 계약은 필수 통과 조건입니다. **Excel의 고정 시간·RSS 임계값은 아직 설정하지 않았습니다.** 따라서 결과 검증 통과와 시간 변화 판정을 구분하며, 결과가 맞았다는 이유만으로 성능 회귀가 없다고 판정하지 않습니다. A–J의 임계값을 Excel 함수 측정에 임의로 적용하지 않습니다. 비용 증가가 의심되면 반복·교대 측정으로 재확인합니다.

히스토리의 Excel Latency는 동기 함수 반환 시간입니다. Jitter 0은 진행 이벤트를 측정하지 않았다는 뜻이며 응답성 합격 지표가 아닙니다. RSS는 10ms 간격의 현재 프로세스 관측값으로 이전 표본·준비 실행의 잔류 메모리까지 포함합니다. 표본별 독립 할당량이나 메모리 상한 준수를 증명하지 않습니다.

## 5. 이후 비교·갱신 규칙

1. 동일 장비·데이터·설정·검색 경로에서 준비 실행을 제외한 반복 중앙값과 범위를 비교합니다. 결과 상한에 도달한 검색과 파일 전체 처리량을 섞지 않습니다.
2. 기준선과 비교본을 가능하면 교대로 실행합니다. 빌드·테스트와 겹친 실행, 준비 실행, 배포 EXE와 소스 실행, 서로 다른 장비는 구분합니다.
3. 5회로 안정적인 P95를 확정하지 않습니다. 차이가 의심되면 반복 수를 늘리고 부하·캐시·원인 계측을 함께 확인합니다.
4. 공식 통과 여부와 기준선 대비 비용 증가를 각각 보고합니다. 검색 계약을 완화하거나 검색 파일·결과를 줄여 얻은 속도를 같은 조건의 개선으로 인정하지 않습니다.
5. 새 기준선을 채택할 때 버전·소스/배포본 구분·엔진 해시·실행 조건·원본 태그를 함께 갱신합니다. 이전 기준과 측정 근거는 성능 개선 기록에, 미채택 판단은 설계 검토 기록에 옮기며 히스토리를 덮어쓰지 않습니다.

실행 절차는 [개발자 가이드 7.3절](DEVELOPER_GUIDE.md#73-벤치마크와-릴리스-검증)을 따릅니다. 다음 예시는 태그 구분 방식이며, 기본 설정 격리·데이터 준비는 별도로 해야 합니다.

```powershell
python scripts/benchmark_performance.py v6.1.1-baseline-warmup
1..5 | ForEach-Object { python scripts/benchmark_performance.py "v6.1.1-baseline-r$_" }
python tools/benchmark_excel_suite.py --repeats 5 --output .qa_excel_suite/results.json --record-tag v6.1.1-excel
```

## 6. 측정하지 않는 범위

- F/G는 JSON/XML 파일의 **일반 텍스트 검색**입니다. JSON/XML 특수 검색과 Python 누락 방지 검색은 별도 측정합니다.
- 결과 목록·미리보기 렌더링, 세션 복원, 시작 화면 지연, EXE 압축 해제와 전체 앱 실행 시간을 포함하지 않습니다.
- A–J 시간은 워커 실행 요청부터 종료 시그널 수신까지입니다. 데이터 생성·프로세스 시작·히스토리 저장 시간은 검색 시간 합계에 포함하지 않습니다. Excel 세트의 함수 호출 시간과 구분합니다.
- RSS는 10ms 간격으로 관측한 현재 프로세스 메모리이며 순간 피크나 모든 자식 프로세스의 메모리를 보장하지 않습니다.
- Excel 세트는 XLSX 대상이며 XLS/XLSB/XLSM·복잡한 스타일·외부 링크·손상 문서·모든 날짜 체계의 성능을 대표하지 않습니다. 수식은 미리 저장된 계산 결과를 검색하며 수식 계산·캐시 없는 수식의 재계산은 측정하지 않습니다. 다수 Excel 동시성·프로세스 풀 준비 비용도 포함하지 않습니다.
