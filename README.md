# StringFinder

대용량 파일과 구조화된 데이터에서 문자열을 빠르게 찾는 Windows 데스크톱 검색 도구입니다.
일반 검색은 Rust 엔진을 우선 사용하고, 정밀 검색이 필요한 경우 Python 경로를 사용합니다.

현재 버전: **5.7.2**

## 5.7.2 변경 사항

- 대용량 JSON 검색을 streaming Visitor 방식으로 처리해 전체 JSON DOM 생성에 따른 메모리 급증을 줄였습니다.
- JSON Unicode escaped 문자열과 비BMP 문자의 검색 정확도를 보강했습니다.
- 파일당 검색 결과 상한, truncation 표시, JSON 깊이·크기 제한을 Rust·Python·UI 경로에서 일관되게 적용했습니다.
- mmap 검색에서 파일 변경을 감지하고 안전한 read-copy fallback을 사용합니다.
- Rust callback 오류를 Python 예외로 전파하고, named-options 기반 `SearchOptions` API를 추가했습니다.
- Windows 동시 파일 교체·truncate 안정성 테스트와 성능 baseline 측정 도구를 추가했습니다.

이번 버전의 전체 검증 결과는 Python `250 passed, 1 skipped, 10 deselected`, Rust `14 passed`입니다. Linux/macOS POSIX 동시 파일 교체 테스트는 해당 OS runner에서 추가 실행해야 합니다.

## 주요 기능

- 폴더와 하위 폴더를 대상으로 하는 고속 문자열 검색
- 파일명·확장자·숨김 항목·바이너리 파일 필터
- 일반 텍스트, XML, JSON, Excel 특수 검색
- XML·JSON·Excel의 부분 일치 및 정확히 일치 검색
- 검색 결과 파일 목록, 매치 목록, 결과·폴더 필터
- 선택한 매치의 전후 문맥 미리보기
- 문맥 미리보기 위·아래 표시 줄 수 설정: 0~20줄, 기본값 5줄
- JSON, XML, Python, JavaScript, 로그 파일의 경량 구문 강조
- 검색 결과에서 파일 열기, 폴더 열기, 설정된 편집기의 해당 줄 열기
- 사용자 지정 편집기 인자 템플릿: `{file}`, `{line}`
- 검색 결과 내보내기와 검색 세션 저장
- 메모리 부족, 접근 오류, 잠금 파일 등의 스킵 내역과 로그 표시
- 한 탭에서 검색 중일 때 다른 탭의 검색 시작 제한

## 지원 검색 모드

### 일반 검색

확장자 필터에 선택된 파일을 일반 텍스트로 검색합니다. 기본 검색은 Rust 엔진의 고속 경로를 사용하며,
파일 인코딩과 검색 조건에 따라 Python 정밀 경로로 처리될 수 있습니다.

### XML·JSON 검색

구조를 해석해 키·값·태그·속성 등 구조화된 필드를 대상으로 검색합니다.
부분 일치와 정확히 일치 모드를 각각 제공합니다.

### Excel 검색

`.xlsx`, `.xlsm`, `.xls`, `.xlsb` 파일을 시트·셀·값 단위로 검색합니다.
검색 결과에서 시트, 셀 주소, 값을 확인할 수 있습니다.


## 빠른 시작

### 배포본 사용

배포본은 별도 설치 없이 실행할 수 있는 단일 실행 파일입니다.

```text
dist/StringFinder.exe
```

1. `StringFinder.exe`를 실행합니다.
2. 왼쪽 폴더 목록에서 검색할 폴더를 추가합니다.
3. 확장자 또는 파일명 필터를 설정합니다.
4. 검색어를 입력하고 `검색`을 누릅니다.
5. 결과 파일을 선택하면 매치 목록과 문맥 미리보기가 표시됩니다.

### 개발 환경에서 실행

Windows와 Python 3.12 이상을 권장합니다.

```powershell
pip install -e ".[dev]"
python build_rust.py
python run.py
```

Rust 엔진을 사용할 수 없는 환경에서는 검색 조건에 따라 Python 경로가 사용될 수 있습니다.

## 검색 옵션

- `정밀 검색`: 유니코드 정규화와 복합 조건 처리가 필요한 검색 경로입니다. 일반 검색보다 느릴 수 있습니다.
- `시스템 항목 제외`: Windows 시스템 항목이나 불필요한 폴더를 검색 대상에서 제외합니다.
- `존재 여부만 확인`: 실제 매치 목록 대신 파일 내 검색어 존재 여부를 빠르게 확인합니다.
- `특수 검색`: XML, JSON, Excel 구조를 해석해 필드 단위로 검색합니다.

검색 중에는 검색 조건 입력이 잠기며, 다른 탭에서 새로운 검색을 시작할 수 없습니다.
현재 검색은 `중지` 버튼으로 종료할 수 있습니다.

## 결과 확인과 외부 편집기

결과 파일을 더블클릭하면 시스템 기본 앱으로 파일을 엽니다.
매치 항목의 `해당 줄 열기` 동작은 설정된 외부 편집기를 사용하며, 기본값은 시스템 기본 앱입니다.

지원되는 편집기 선택지는 다음과 같습니다.

- 시스템 기본 앱
- Visual Studio Code
- Cursor
- Notepad++
- Sublime Text
- 사용자 지정 실행 파일

사용자 지정 편집기는 설정에서 다음과 같이 인자 형식을 지정할 수 있습니다.

```text
--line {line} {file}
```

`{file}`은 파일 전체 경로로, `{line}`은 검색된 줄 번호로 치환됩니다.
실행은 쉘을 거치지 않으므로 인자 템플릿에 명령문을 직접 입력하는 방식은 지원하지 않습니다.

## 문맥 미리보기

매치 항목을 선택하면 해당 줄 주변의 내용을 확인할 수 있습니다.

- 위 문맥과 아래 문맥을 각각 0~20줄로 설정
- 기본값은 위 5줄, 아래 5줄
- 설정은 프로그램 재실행 후에도 유지
- 큰 줄은 표시 길이를 제한해 UI 메모리 사용량을 보호
- 파일 읽기는 백그라운드에서 수행해 느린 저장장치에서도 UI 응답성을 유지

## 안정성과 성능 설계

StringFinder는 검색 속도뿐 아니라 검색 실패와 자원 고갈 상황의 예측 가능성을 중요하게 다룹니다.

- Rust 기반 Aho-Corasick·메모리 매핑 경로로 일반 검색을 가속합니다.
- Python 기반 프로세스 풀은 정밀 검색과 일부 예외 경로에서 제한적으로 사용합니다.
- 결과는 배치 단위로 UI에 전달해 대량 결과의 렌더링 부담을 줄입니다.
- 파일당·전체 매치 수 상한을 둬 결과 폭증을 제한합니다.
- 바이너리 파일 제외 옵션을 제공해 불필요한 대량 읽기를 줄입니다.
- JSON 파싱 메모리 한계 기본값은 500MB입니다.
- 지나치게 깊은 JSON과 과도한 셀 검사를 제한합니다.
- 접근 불가·잠금·인코딩 문제 파일은 로그와 스킵 목록으로 구분합니다.
- 메모리 부족으로 검색이 중단되면 사용자 안내 팝업을 표시합니다.

검색 결과는 파일 접근 권한, 파일 변경 시점, 인코딩, 필터 설정의 영향을 받습니다.
스킵된 파일이 있는 경우 로그 탭에서 원인을 확인해야 합니다.

## 설정과 저장 데이터

다음 항목은 사용자 설정으로 저장됩니다.

- 테마와 창·분할 영역 배치
- 폴더·확장자·파일명 필터
- 검색어 및 파일명 필터 이력
- 문맥 미리보기 줄 수
- 외부 편집기와 사용자 지정 실행 인자
- 로그 보관 설정
- 고급 검색 상한과 타임아웃
- 탭 순서와 세션

Windows에서는 일반적으로 다음 위치에 설정과 세션 데이터가 저장됩니다.

```text
%APPDATA%\StringFinder\
```

설정 파일을 직접 편집해야 하는 경우에는 프로그램을 종료한 후 백업하고 수정하십시오.

## 개발자 가이드

### 기술 스택

| 영역 | 기술 |
|---|---|
| UI | Python 3.12+, PySide6, pyqtdarktheme |
| 검색 엔진 | Rust 2021, PyO3, Aho-Corasick, memmap2, rayon |
| 구조 파일 | python-calamine, quick-xml, serde_json |
| 동시성 | Qt QThreadPool, ProcessPoolExecutor, multiprocessing.Manager |
| 테스트 | pytest, pytest-qt, pytest-benchmark |
| 품질 검사 | Ruff, mypy, Cargo Clippy |
| 배포 | PyInstaller, Cargo, build.py |

### 프로젝트 구조

```text
StringFinder/
├─ src/
│  ├─ assets/           # 아이콘과 리소스
│  ├─ core/             # 검색 엔진 호출, 워커, 시스템 연동
│  ├─ rust_engine/      # Rust 검색 엔진과 빌드 산출물
│  ├─ sf_utils/         # 설정, 문자열, 로거, 파일·리소스 유틸리티
│  ├─ ui/               # 메인 창, 검색 탭, 필터, 결과 화면
│  └─ sf_main.py        # 애플리케이션 진입점
├─ tests/               # 자동화 테스트
├─ run.py               # 개발 실행
├─ build_rust.py        # Rust 엔진 빌드
├─ build.py             # 배포본 빌드
└─ pyproject.toml       # Python 패키지와 도구 설정
```


## 배포본 빌드

프로젝트 루트에서 다음 명령을 실행합니다.


## 문제 해결

### 검색 결과가 일부만 표시되는 경우

전체 매치 수 또는 파일당 매치 수 상한에 도달했을 수 있습니다. 결과 요약과 로그 탭에서 제한 또는 스킵 메시지를 확인하십시오.

### 파일이 검색되지 않는 경우

확장자·파일명 필터, 숨김 항목 제외, 바이너리 제외 설정을 확인하십시오. 접근 권한이나 파일 잠금으로 스킵되었을 수도 있습니다.

### JSON 검색이 중단되는 경우

파일 크기, JSON 깊이, 파싱 메모리 한계를 확인하십시오. 시스템 가용 메모리가 낮은 경우 다른 프로그램을 종료한 뒤 다시 시도하십시오.

### 외부 편집기가 열리지 않는 경우

설정된 실행 파일 경로가 실제로 존재하는지 확인하십시오. 사용자 지정 편집기는 인자 형식에 `{file}`을 포함하는 것을 권장합니다.
